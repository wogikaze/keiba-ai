# 探索 04: 新しい学習データを重くする（半減期 5 年）

仮説探索（[ADR 0005](../../docs/adr/0005-market-features-and-search-protocol.md)）。`scripts/run_search.py` で走らせる。
基準は search-01（features_v1 の市場オフセット LightGBM、market-combination と同じ設定）。採否は valid の Δ だけで決め、test は参考値。

## 仮説

（実行前に書いた）市場の効率と馬券の売れ方は年とともに変わる（10 分前と確定の差が広がっている）。新しいレースを重くすると valid Δ が 0.001〜0.002 良くなる。

## 変更点

02 の設定に、学習の重み 0.5^(2019 年からの年数 / 5) を付ける。

## 結果

`results.json`（git 451a181、作業ツリー 変更あり: ?? src/keiba_ai/features_rating.py、103 秒）。

| | valid | test（探索中の参考値） |
|---|---|---|
| logloss（モデル / 10 分前の市場） | 1.9731 / 1.9968 | 1.9262 / 1.9453 |
| Δ（開催日の 95% CI） | -0.0237 [-0.0282, -0.0195] | -0.0191 [-0.0226, -0.0155] |
| 開催日 SE | 0.0022 | 0.0018 |

- test の年ごとの Δ: 2022 -0.0160, 2023 -0.0204, 2024 -0.0157, 2025 -0.0244。
- Benter（valid で当てはめ）: α 0.948（SE 0.044）、β 0.041。プラセボ（レース内で並べ替え）の α: -0.001, +0.008, +0.004, +0.003, +0.014（SE ≈ 0.007）。
- 学習: best_iteration 840、特徴量 100 列。gain の上位: mk_q_vs_win 0.055, mk_logodds 0.035, race_symbol_code 0.031, h_corner4_mean3 0.022, horse_weight 0.022, h_days_since 0.020, venue_code 0.019, h_l3f_mean3_z 0.019。

## 結論

**不採用。** valid Δ −0.0237 で 02（−0.0253）より悪い。新しいレースを重くすると学習データが実質的に減る損の方が大きい。
