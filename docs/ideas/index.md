# 研究アイデア

思いついた段階のアイデアを1件1ファイルで置く。実験に進めるものは `experiments/` に移し、設計判断が要るものは ADR にする。

## すべてのアイデアに共通する評価の原則

先行研究から、新しい情報源を足すときの評価方法はほぼ決まっている。

1. **比較対象は市場オッズ。** JRA の最終単勝オッズは、過去成績のモデルより順位の予測精度が10ポイント以上高い（[森ほか 2010](../literature/2010-mori-keiba-yoso-shuudanchi.md)）。LLM エージェントも締切オッズに大きく負ける（[JockeyBench 2026](../literature/2026-xie-jockeybench.md)）。新しい情報の価値は「オッズだけのモデル」に対する対数損失の改善（ΔlogLoss、[Benter](../literature/2019-benter-model.md) の ΔR²）で測る。
2. **時刻を必ず記録する。** 情報が公開された時刻と、馬券を買う時刻を比べる。締切直前の情報はオッズにすぐ織り込まれる（[Hanyu ほか 2025](../literature/2025-hanyu-last-minute-dynamics-parimutuel.md)）。確定オッズで評価するとリークになる。
3. **特徴量を足しても良くなるとは限らない。** ドメイン知識から作った特徴ブロックを足すと、かえって悪化した例がある（[杉浦 2026](../literature/2026-sugiura-leakage-aware-evaluation.md)）。1ブロックずつ足して効果を測る。
4. **収集の可否を先に確認する。** SNS・配信・有料記事は、利用規約と著作権で使える範囲が決まる。生データは `data/raw/`（git 管理外）に置き、公開リポジトリには入れない。
