# ニュース・note の活字情報を LLM で特徴量にする

> 一言で: 競馬ニュース、厩舎コメント、調教レポート、note の予想記事などを LLM で読み、「状態が良い」「距離が不安」などの判断を、時刻つきの構造化データにして特徴量にする。

## 何を得るか

- **陣営の評価:** 厩舎・騎手のコメントから、状態の良し悪しや狙いのレースかどうかを抽出する。
- **調教の評価:** 調教タイムの数値だけでなく、記者の評価（「動きが重い」など）を抽出する。
- **予想家の印の集計:** 予想記事の本命・対抗を集めて、予想家ごとの的中傾向も学習する（[アイデア 0005](./0005-crowd-and-books.md) と共通）。
- **急な情報:** 出走取消、乗り替わり、馬体の異常。

## 先行研究

- [JockeyBench 2026](../literature/2026-xie-jockeybench.md): JRDB の情報を「公開時刻」つきで再生し、LLM に予測させた評価環境。最良のエージェントでも締切オッズに大きく負けた。時刻つきで情報を再生するという作り方は、そのまま参考になる。
- [Hanyu ほか 2025](../literature/2025-hanyu-last-minute-dynamics-parimutuel.md): 締切直前のオッズの動きには情報がある。活字情報がオッズより先に出ていれば価値があり、後なら価値がない。
- [Hubáček ほか 2019](../literature/2019-hubacek-exploiting-betting-market-ml.md): モデルをオッズと似せない（相関を下げる）ように学習すると収益が出やすい。活字情報は市場と違う情報を入れる手段になりうる。

## 必要なデータ

- ニュースサイト・note・ブログの記事本文と、**公開時刻**（更新時刻ではなく）。
- 収集時刻もあわせて記録する。過去分をあとから集めると、公開時刻が分からないことがある。

## 最初の検証

1. 1か月分のレースについて、関連記事を集め、LLM で「馬ごとの評価（-2〜+2）」と根拠の文を抜き出す。
2. 公開時刻が「馬券を買う時刻」より前の記事だけを使う。
3. オッズだけのモデルに、記事の評価を足したときの ΔlogLoss を測る。締切30分前のオッズと最終オッズの両方で比べる。

## リスク

- 有料記事・note の有料部分は、利用規約で機械処理を禁じていることがある。
- LLM の学習データに、評価期間の結果が入っている可能性がある（未来の情報のリーク）。LLM には記事の要約と抽出だけをさせ、勝ち馬の予想はさせない。
- 公開記事の情報は、ほとんどオッズに織り込まれている可能性が高い。
