# 競馬予想で始める機械学習〜完全版〜（dijzpeb 2020）

> 一言で: YouTube 連載に沿って、netkeiba のスクレイピングから LightGBM の3着内予測、回収率シミュレーション、実際の購入までのコードを公開した Zenn の本。いいね1,400超、購入者コミュニティ約1,400名で、日本の個人競馬AIの「定番の型」（netkeiba 4テーブル + LightGBM 二値分類 + 回収率シミュレーション）を広めた源流の1つ。無料部分にはデータ取得と運用の設計はあるが、モデル評価の章は有料。

本ノートは無料公開章（「はじめに」、第2章「スクレイピング」、第6章「実際に賭けてみた結果・・・」、【v2.1.1】の概要・ディレクトリ構成と実行コード・constants・preparing 前半、動画第1〜4回のソースコード）に基づく。前処理後半、学習（第4章・第15章）、回収率シミュレーション（第5章・第16〜17章）は有料で読んでいない。ソースコード本体は Gist 埋め込みや購入者限定リポジトリにあり、取得したテキストには含まれていない。

## データ

- netkeiba.com からスクレイピングする4テーブル（第2章の表）: レース結果（`Results.scrape()`）、馬の過去成績（`HorseResults.scrape()`）、5世代62頭分の血統（`Peds.scrape()`）、払戻表（`Return.scrape()`）。v2 ではこれにレース情報テーブルと馬の基本情報テーブルが加わり、当日は出馬表ページを同じ形に加工する（【v2.1.1】概要「使用するデータ」）。
- レース ID を生成して `pd.read_html` で取る。払戻表は改行タグが消えて複勝・ワイドの値がつながるので、`<br>` を文字列に置換してから読む。
- 2024年11月の netkeiba の仕様変更で、user-agent の設定が必要になった（第2章の追記）。間隔は2〜3秒を推奨。
- 例の期間は 2019年の全レース（旧版）、2021年（v2）。

## 特徴量

- 馬の過去成績を馬ごとに集計（「直近5レースの結果」など）してレース結果に結合（【v2.1.1】概要「学習時の流れ」）。
- 血統、レース情報（距離・天気など）、馬の基本情報、馬体重と体重変化（「計不」「前計不」の処理）。
- 更新履歴に「上がりタイム」の追加、「特徴量を追加し、回収率144%→151%」（2020/12/15）とある。特徴量の一覧は有料部分。

## モデルと目的変数

- LightGBM の二値分類。目的変数は「3着以内に入ったかどうか」（【v2.1.1】概要）。予測スコアは3着内確率で、レース内の相対的な強さとして使う。
- Optuna の LightGBM チューナーを使う（「必要なパッケージ」の import、更新履歴「optunaを使うことで回収率120%→144%」）。
- 実際に賭けるときは、過去レース全体で学習し直す（第6章「（事前準備）訓練」）。

## 評価

- 訓練データとテストデータに分けて学習し、テストデータと払戻テーブルで回収率をシミュレーションする。分割方法の詳細（時系列か）は無料部分では確認できない（有料の第4〜5章）。
- 馬券の種類は単勝から始まり、馬連・ワイド・三連複・三連単、馬連BOX が後から追加された（更新履歴 2021/5/15、2021/1/8）。回収率シミュレーションには標準偏差のプロットとシャープレシオの説明が追加されている（2021/2/25、2021/3/2）。
- 単勝の「適正回収値」というコードもある（2021/2/7）。

## 結果

- 回収率（シミュレーション）: 120% → 144%（Optuna 導入、2020/11/13）→ 151%（特徴量追加、2020/12/15）（「はじめに」の更新情報）。条件（期間、賭け方、閾値）は無料部分に書かれていない。
- 実際の購入（第6章）: 2021年日本ダービーの日に東京・中京の全レースで運用。「スコア1.3あたりを超える馬が3頭以上なら三連複BOX、2頭以下なら単勝」というルールで、ダービーの4番人気シャフリヤール（単勝 7,020円の払戻）と中京5R の7番人気（3,460円）が当たり、1日の収支はプラス。

## 落とし穴と教訓

- **horse ページは取得日によって中身が変わる**（【v2.1.1】preparing 前半「scrape_html_horse_with_master()」）。同じ馬のページでも、取得した日以降のレースが追加されている。v2 では horse_id ごとの取得日時をマスタ（`horse_results_updated_at.csv`）に記録する。過去成績を集計するときに対象レースの日付で切らないと、未来のレースが混入する。
- **データ更新時の重複**: 馬の過去成績を追加取得して `pd.concat` すると古い行が重複する。両方にある horse_id は新しい取得分を使う `update_data` 関数を用意している（第2章）。
- **継続運用のための構造化**: 旧版の Notebook から、modules/ にコードを分け、サイト上の列名やファイルパスを定数化した v2 へ移行した。netkeiba の仕様変更の影響を1箇所の修正で済ませるため（【v2.1.1】constants）。
- v2 の開発はここで完結し、自動投票やサーバー運用まで含む新シリーズ（note 連載）に引き継がれている。

## 批判的に読む

- 回収率 120% → 151% は、条件が公開されていない単一のシミュレーション値。テスト期間の長さ、分割方法、閾値の選び方、使ったオッズ（確定オッズか）が無料部分で分からない。閾値をテスト期間で選んでいれば選択バイアスで上振れる。
- 過去成績の集計で、horse ページの取得日以降のレースを除く処理が正しく入っているかは、無料部分では確認できない。この型を真似た個人記事では、このリークがよく問題になる（[gara_gara 2020](./2020-gara-gara-lightgbm-leak.md)）。
- 第6章の実購入は1日だけで、統計的な意味はない。高配当2本でプラスになっており、著者自身も「期待できそう」と書くにとどめている。
- 3着内の二値分類はレース内の相対性（同じレースの他の馬との比較）を扱わない。スコアをレース内で正規化しているかは無料部分では不明。
- それでも、netkeiba のテーブル構成、払戻表のパース、当日の出馬表との整合（学習データと同じ形に加工する）という実務の要点がまとまっており、後続の多くの個人実装の土台になっている。

## keiba-ai での使い方

- **netkeiba 取得の参照実装**: 払戻表の `<br>` 置換、5世代血統の重複除去、レース ID の構造などは、`src/keiba_ai/` のスクレイパーを書くときの確認リストになる。
- **取得日時の記録**: horse ページのような「取得するたびに中身が増える」ページは、取得日時を `data/raw/` のメタデータに保存する。特徴量生成では、対象レースの日付より前の行だけを使うことをテストする。
- **学習時と当日の整合**: 出馬表から作る推論用データと、レース結果から作る学習用データで、列と前処理を同じ関数に通す設計は採用する価値がある。
- **比較対象**: 「netkeiba + LightGBM 3着内二値 + 単勝回収率」はこの分野の標準的なベースラインになる。keiba-ai の初期ベースラインをこの型で作り、ランキング学習や市場確率との結合と比べる。
