# netkeiba → SQLite → LightGBM の連載。3連複×期待値フィルターで 124.7%、スピード指数の追加で 110.8%

> 一言で: Claude Code にコードを書かせて netkeiba のスクレイピング、SQLite、LightGBM、バックテストまで作った全10回＋αの連載。#01 の要約では、2,209 レースでモデル1位の単勝 78.4%、上位3頭の3連複 81.2%、3連複に期待値フィルターをかけた「戦略E」が 339 レースで 124.7%。#13 では西田式スピード指数（過去走の集計値）を足して、オッズなしモデルの単勝1位が LightGBM で 76.6% → 78.6%、レース選別と組み合わせた3連複1点が 90.3% → 110.8%（1,266 レース）。

#01 は2026年5月12日公開、無料。連載本体（#02〜#10）は有料なので取得していない。#13 は匿名アクセスで本文全体が表示されたので、表示された範囲を添付として保存した。

## データ

- netkeiba からスクレイピングし SQLite に保存。レート制限、robots.txt の確認、EUC-JP の判定、中断からの再開を入れている（#01「Claude Code で『全部やってもらった』」の節）。
- 5か月分（約 1,440 レース）から始め、最終的に4年分 11,387 レースまで集めた（#01「なぜ機械学習が競馬に使えるのか」）。
- 落とし穴: netkeiba のカレンダーページには地方競馬も載っており、2026年1月4日に 69 レースが検出された。JRA の race_id（12桁）の5〜6文字目の会場コード 01〜10 で絞る（#01「69レース問題」）。

## 特徴量

- #01 の例示: 過去5走、騎手の勝率、距離適性、馬場、オッズ。
- #13 のスピード指数: 西田式の簡易版。基準タイムはコース・芝ダ・距離ごとの走破タイムの中央値（件数 50 未満のバケットは芝ダ・距離の中央値に退避）、距離指数は 1000/基準タイム、馬場指数はそのレースの中央値タイムと基準の差、斤量は 55kg 基準で 1kg あたり 2。
- 指数そのものは当該レースの結果から計算されるので特徴量に入れず、`shift(1)` で当該レースを除いた直近5走平均とキャリア最高だけを入れる。著者はここを「一番大事なポイント」としている。
- 基準タイムのバケットのうち 133 個中 24 個が 100 件未満で、障害や特殊距離の 13 件しかないバケットで中央値が振れていた。別の AI（Codex）のコードレビューで気づいた（#13「落とし穴 Tips」）。

## モデルと賭け方

- LightGBM で1着確率を予測。#13 では XGBoost・CatBoost も並べている。
- #07 はオッズなしモデル、#10 は Harville モデルで3連複の確率に変換して期待値フィルターをかける「戦略E」（#01 の目次）。
- 「★DE」は中穴狙いのレース選別（#13）。条件の中身は無料部分には書かれていない。

## 結果

#01「このシリーズの最終ゴール」の表（連載 #10 時点のバックテスト）:

| 戦略 | 対象 | 回収率 |
|---|---|---|
| 単勝（AI 1位） | 2,209R | 78.4% |
| 3連複（AI 1〜3位） | 2,209R | 81.2% |
| 戦略E（3連複×期待値フィルター） | 339R | 124.7% |

#13「before / after の検証コマンド」の節（オッズなしモデル、学習に使っていない score 期間 1,602 レース、単勝1位を 100 円）:

| モデル | 追加前 | 追加後 |
|---|---|---|
| LightGBM | 76.6% | 78.6% |
| CatBoost | 77.0% | 80.4% |

★DE のレース選別と組み合わせた3連複1点（2026年1〜5月、1,266 レース）: 90.3% → 110.8%。#13 の冒頭では「78.4% → 110.8%」と書かれており、記事内で比較の起点が揃っていない。
目次によると #05 で回収率 111%、#06 で「期待値フィルターの対象が 0.8% しかなかった」、#08 で「3〜6倍帯にだけシグナルがあった」という回がある（有料で未読）。

## 落とし穴と教訓

- 結果から計算される指数は、必ず過去走だけの集計にしてから特徴量にする。
- グループ集計（中央値・平均）で作る特徴量は、各グループの件数を確認し、薄いグループは粗い単位に退避させる。

## 批判的に読む

- スピード指数の基準タイムは、データ全体（テスト期間を含む）の中央値で計算している。過去走の指数を集計するときにも、未来のレースを含む基準タイムを使うので、弱いリークになる。基準タイムはその時点までのデータで計算するべき。
- 単体モデルの改善は +2.0〜+3.4 ポイントで、どれも 80% 前後（控除率の水準）。100% を超えるのは、レース選別（★DE）や期待値フィルターで対象を絞った後の数字だけ。条件をバックテストで探して同じ期間で評価している可能性があり、選択バイアスが大きい。339 レースの3連複の回収率は数本の高配当で大きく動く。
- 期待値計算に使うオッズが確定オッズか発走前のものかは、無料部分に書かれていない。
- 連載本体が有料なので、方法の大半は確認できない。

## keiba-ai での使い方

- スピード指数を特徴量に入れるなら、基準タイム・馬場指数を「その日より前のデータだけ」で計算する実装にする（ローリングの中央値）。件数が少ないバケットは退避させる。
- 単体モデルの回収率（単勝1位）と、レース選別後の回収率を必ず分けて報告する。選別条件は検証期間で決め、テスト期間では固定する。
- netkeiba のカレンダーから JRA の race_id を抽出するときは会場コード 01〜10 で絞る。
