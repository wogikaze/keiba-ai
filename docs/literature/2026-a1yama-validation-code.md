# 競馬AIの検証コード46,000行と、合格を疑うコード0行（a1yama 2026）

> 一言で: オフライン検証で合格した施策が本番で3回同じように崩れた。検証スクリプトは252本・約46,000行と実装（約21,000行）の倍あったが、すべて「合格を出す装置」で、合格を疑う装置は1本もなかった。入力のリークを直して walk-forward をやり直すと、学習量が増えるほど条件を満たす買い目が消えた。合格していたのはモデルが弱い年だけだった。

## データ

- JRA。walk-forward の各フォールドの学習量は 2019 年テストで 6,905 レース、2026 年テストで 30,868 レース。データの入手元は書かれていない。

## 特徴量・モデル

- 詳細は書かれていない。「市場情報を入れたモデル」と、モデル確率と市場を混ぜる較正（ブレンド）が登場する。

## 評価

- 年単位の walk-forward（フォールドごとに再学習）。
- 確定オッズの hold-out で合格したルールを実運用に入れた。

## 結果

冒頭の表（オフライン検証 → 前向きの実測）:

| 施策 | オフライン | 前向き |
| --- | --- | --- |
| 3連単の期待値ルール | 回収率 180% | 45% |
| 市場情報を入れたモデル | 市場超過 +4.5pt | +0.8pt |
| 連系（馬連・馬単・3連複） | 8年の walk-forward で 7〜8年合格 | 買い目そのものが消えた |

「8年中7年合格は頑健性の証明ではありませんでした」の節。入力の漏洩を直して引き直した結果:

| テスト年 | 学習量 | 条件を満たす買い目 |
| --- | --- | --- |
| 2019 | 6,905R | 1,267 |
| 2021 | 13,763R | 806 |
| 2023〜2025 | 20,646〜27,417R | 0 |
| 2026 | 30,868R | 13 |

- 2023 年と 2024 年のフォールドでは、較正の結果「モデルを混ぜない方が尤度が高い」だった。
- 実運用では連敗し、全ルールを停止した。

## 落とし穴と教訓

- **弱いモデルほど市場と食い違うので、期待値の裾が太くなる。** その裾をエッジと読んでいた。本番は全データで学習するので、合格した年の条件は本番に最も似ていないフォールドで作られていた。
- 合格が出るまで期間・券種・閾値・フィルタ・シードを変えるループは、記録のない多重比較だった。試した回数すら残っていない。
- 不合格なら検証を疑うが、合格なら疑わない、という非対称。
- オフラインと前向きの乖離を「前向きは悪く出るもの」で流していたが、正体は入力の漏洩だった。
- 次の判定ルール（「次はどう判定するか」）:
  1. 合否は前向きの台帳だけで決める。オフラインは足切りまで。
  2. オフライン検証を書く前に、前向きの記録の口を先に用意する。
  3. 乖離が出たらまず入力を疑う。運や分散はその後。
  4. walk-forward の年別成績には、必ずフォールドの学習量を併記する。逆相関していたら年次変動ではない。

## 批判的に読む

- 具体的なモデル・特徴量・リークの中身が書かれておらず、表の数値を再現する手段はない。
- 「学習量が増えるほど買い目が消える」は、モデルが市場に近づき、期待値の閾値を超える馬が減るという説明と整合する。ただし同時期に市場自体の効率も上がっている可能性があり（[rindokulab 2026](./2026-rindokulab-recovery-100-discarded.md) の「年10ポイントで消えたエッジ」）、2つは分けられていない。
- 確定オッズで合格判定していた点も、前向きとの乖離の一因になりうる。

## keiba-ai での使い方

- **walk-forward の結果表に、フォールドごとの学習データ量（レース数）と、モデルと市場の食い違いの大きさ（例: KL や log-loss 差）を必ず並べる。** 成績が学習量と逆相関していたら、エッジではなく弱さを見ている疑い。
- 本番に近いのは最後のフォールド（学習量が最大）なので、主に読むのはそのフォールドにする。
- 試した設定（期間・券種・閾値）を実験ディレクトリに全部残し、[Bailey 2017](./2017-bailey-probability-backtest-overfitting.md) の PBO や Deflated Sharpe で選択バイアスを補正する。experiments のルール（結果を書き換えない、新しいディレクトリを作る）はこの記録の役も兼ねる。
- 前向き評価の台帳（買う時点のオッズ、買い目、結果）を、オフライン検証より先に作る。
