# JV-Link を Python から無人で回す（crossclub_lab 2026）

> 一言で: JRA-VAN の JV-Link（COM 部品）を Python（pywin32）から無人で回し、1999〜2026 年の RACE データ 372万件を取り込んだ記録。最初は毎秒 21 件で丸2日かかる計算だったが、JVOpen を1年ずつ期間指定で開くと取得は 14 分で終わった。速くなった途端に JVGets のメモリ漏れ（1件約 110KB）で 6GB を超えて落ち、JVRead に切り替えて解決した。

モデルや回収率は扱わない（「ここから先は別の記事に書く」）。JRA-VAN からデータを取る実務の知見として記録する。

## データ

- JRA-VAN Data Lab.（JV-Link、64bit 版）を、無料お試し期間（インストールから1か月）に利用。
- 取得した種別: RACE（レース結果）、DIFN（馬・騎手などの台帳）、BLOD、SNAP、SLOP、WOOD（ウッドチップ調教）、YSCH、HOSE、HOYU、COMM、MING など。
- 最終結果（「結果: RACE 28 年分の実数」）: 1999〜2026 年、3,720,038 件、28 ファイル・16.3GB。取得 14 分、SQLite への取り込み 2 時間 28 分、メモリは最大 170MB 前後。
- 内訳: SE（馬毎レース情報）2,055,586、JG（競走馬除外情報）774,069、RA（レース詳細）169,575、オッズ O1〜O6 各 6〜9 万、払戻 H1/H6/HR 各 6〜9 万、WF 840。

## 8つの失敗と直し方（「8 つの失敗と直し方」の表から）

1. **セットアップのダイアログで JVOpen が戻らない。** option 4（NODIALOG）でも出た。押す操作が UIAutomation に公開されていないため、部品の位置を取ってマウスでクリックする PowerShell を別プロセスで2秒おきに走らせる。.ps1 は BOM 付き UTF-8 で保存しないと日本語の部品名が化けて、エラーも出ずに止まる。
2. **WOOD だけ option 4 で -301（認証エラー）。** WOOD だけ option 1（通常）に上書きすると通った。
3. **種別をまとめて開くと遅い**（仕様書の注意）。種別ごとに開き、終わった種別を状態ファイルに記録して再開できるようにした。
4. **約5時間後、JVGets が件数ありで中身 None を返して例外。** 1件飛ばして件数を数える。5万件ごとに進捗を出す。
5. **レコード末尾にすでに改行と NUL が付いている。** そこへ改行を足して書いたため NUL だけの行が倍できた。`rstrip(b"\r\n\x00")` してから書く。
6. **対話セッションの裏で走らせた長時間の取得が途中で止まった。** タスクスケジューラから cmd で動かし、`-u` と `PYTHONIOENCODING=utf-8`、最後に終了コードをログに残す。
7. **全期間を一度に開くと毎秒 21 件。** 遅さは1回の JVOpen で開くファイル数で決まり、2乗に近い形で伸びた（4,318 ファイルで毎秒 21 件、77 ファイルで毎秒 6,512 件）。JVGets を JVRead に替えても、バッファを減らしても変わらなかった。fromtime の「開始-終了」で1年ずつ開くと、1999 年分（97,437 件）が 1 時間 15 分から 13 秒になった。ただし DIFN（台帳）は期間指定で開くと全部「該当なし（-1）」になり、0件で取得済みと記録されてしまう。ファイル数が 300 を超えるときだけ分ける。
8. **JVGets が1件ごとに受け取りバッファ分のメモリを残す。** バッファ 110,000 バイトで3,000件あたり +356MB、2,048 バイトで +9MB。gc.collect() でも戻らない。JVRead（文字列版）に切り替え、cp932 に戻したバイト列が JVGets と同じことを 3,000 件で確認した。

## 落とし穴と教訓

- 「遅い」は我慢する前に条件を変えて測る。開くファイル数を変えただけで 300 倍速くなった。
- 速くした直後にメモリを見る。遅いときは目立たなかった漏れが表に出る。
- 件数・行数など数えられるものを数える。NUL 行が2倍、飛ばしたレコード数、年ごとに開いたファイル数の合計（3,970）と一括（4,318）の差 348 など。差 348 の原因（重複か欠落か）は未確認で、DB 側で突き合わせる予定。
- 黙って飛ばさず、飛ばした件数を出す。後でデータの欠けを見積もれる。

## 批判的に読む

- 速度とメモリの測定は1台の環境で、JV-Link や pywin32 の版による違いは確かめていない。-2 や -301 の原因も推測にとどまる。
- 年ごとに開いたときのファイル数の差（348）が未解決で、年の境目でデータが欠けている可能性が残る。この種別ごとの件数照合なしにモデルを作ると、欠けた期間が偏りになる。
- お試し期間内で一括取得した後の継続利用（利用規約・月額）には触れていない。

## keiba-ai での使い方

- JRA-VAN を `data/raw/` の入手元にする場合、取得スクリプトは「種別 × 年」単位で開き、単位ごとの完了状態・件数・飛ばした件数を `data/raw/` のマニフェストに記録する。`data_version` の根拠にもなる。
- 台帳系（DIFN など）は期間指定が効かないので、全期間で開く分岐を設ける。0件で完了扱いにしない検査を入れる。
- JVGets ではなく JVRead を使う。改行と NUL を落としてから保存する。
- 取り込み後に、年ごと・種別ごとの件数と、RA（レース）と SE（出走馬）のキーの整合を確認するチェックを用意する。
