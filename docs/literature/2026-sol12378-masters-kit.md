# 大会で「いつリスクを取るか」を動的計画法で決めた参加実装 — 市場に勝つ方法ではないと明言した公開キット

> 一言で: AI競馬予想マスターズ2026（仮想ポイントで所持ポイントを競う大会）の参加者が、使った手法を一般化して公開したリポジトリ。予測モデルは「控除を除いた三連単の市場確率」と「単勝オッズからの Harville 確率」の 2 値だけを使う小さな対数線形モデルで、市場確率に 5% だけ混ぜる程度。合成データでの holdout NLL の改善は 5.80 のうち約 0.015 にとどまる。勝負所は「残りレース数と所持ポイント」から賭ける価格帯・点数・金額を決める動的計画法で、利益の出る賭け方ではなく「いつリスクを取るか」を決める道具だと著者自身が書いている。大会では好成績だったが、的中は 204 レース中 4 回で、運の部分が大きいとしている。

原本は README（`library/2026-sol12378-masters-kit/source.txt`）と、手法の説明 `docs/05-model-pipeline.md`（添付 `attachments/model-pipeline.txt`）。大会中に実際に動かしたスクリプトは `submission/` に当時のまま入っている、とある（大会運営の了承済み）。

## データ

- 判断時点のオッズ（三連単全組合せと単勝）だけを使う。結果・オッズの実データは権利の都合で同梱せず、同じ形式の合成データ生成器を入れている（「データについて」の節）。
- 大会での投票: 8/29〜9/19 の 190 レース（方策表を直接使ったのは 8/29 の 29 レース）と 9/20 の 14 レース、計 204 レース（「大会で実際に使ったコード」の節）。

## 特徴量

model-pipeline の「特徴量」の節:

1. 三連単オッズから求めた控除除去後の確率の対数。控除はオッズの逆数をその合計で割る単純な方法で除く。推定パラメータが要らないのはこれだけで、複雑な方法を使うと「市場の見方」の列に自分の推定が混ざるから、という理由。
2. 単勝オッズから Harville で求めた三連単確率の対数。Harville は人気薄の上位入線を過小評価する偏りが知られているので、単独の予測としては使わず「市場から得る 2 つ目の値」として扱う。

## モデルと目的変数

- 目的: レースごとに、オッズの出ている三連単の全組合せの上で softmax 分布を作り、実際の的中組合せの確率を最大化する（条件付きロジットと同じ形）。1 レース = 1 観測。数百レースあっても標本としては小さい、と注意している。
- 損失: レースごとの NLL の平均＋正則化。正則化は市場確率の重みを 1、Harville の重みを 0 に引き寄せる。つまり「オッズだけ」が基準で、離れるには予測の改善が要る。重みの範囲は [0.5, 1.5] と [0, 0.5]、L-BFGS-B で最適化。
- 学習と評価は日付で分ける（`--holdout-from`）。
- 最終確率 = 0.95 × 市場確率 + 0.05 × モデル（パイプライン図）。

## 賭け方（方策表と配分）

- 方策表: 状態 = (残りレース数, 所持ポイント)、行動 = (価格帯, 点数, 1 点あたりの金額)。最後のレースから逆向きに、目標残高への到達確率を最大にする行動を計算する（動的計画法）。
- 価格帯ごとに払戻率 R を置き、オッズ O の馬券の的中確率を R/O とする。R < 1 なのでどの行動も期待値はマイナスで、方策表が決めるのは「いつリスクを取るか」だけ。R に 1 を超える値を入れるとソルバはそれを優位性として扱ってしまう、と注意している。同梱の R は公表控除率からの目安で、実測値ではない。
- 目標残高方式: どの馬券も 1 枚的中で目標に届く金額にし、確率/金額の上位 200 候補から 100 ポイント単位のナップサック問題で配分する。同じレースの馬券は同時に当たらないので、的中確率は選んだ馬券の確率の和。
- `odds_factor` = 0.80: 締切まで賭けが集まり続けるので、的中馬券の確定倍率は賭けた時点より低いのが普通。賭けた時点のオッズで金額を決めると目標にわずかに届かないことが続く、という実運用の知見。
- 価格帯の中での選択は、価格の近さ（95%）とモデル確率の順位（5%）を値ではなく順位で組み合わせる。

## 結果

- 合成データでの重み ≈ [0.935, 0.0]。Harville の重みは下限 0 に張り付く。三連単オッズがあれば単勝からの Harville は新しい情報を足さない、と解釈している（model-pipeline「結果の読み方」）。
- holdout NLL の改善: 5.80 のうち約 0.015。著者は、これは利益の根拠にも確率の正確さの根拠にもならない、と明記している。
- 方策表の到達確率（初期 1,000,000、上限 0.421）: 刻み 25,000 で 0.296、5,000 で 0.397、2,500 で 0.408。シミュレーションでの到達率 0.406。最終残高の平均は約 810,000、中央値は約 35,000（「シミュレーションで確かめる」の節）。一か八かの方策であることを中央値が示している。
- 大会: 良い結果だったが、的中は 204 レース中 4 回（README「限界と注意点」）。

## 落とし穴と教訓（著者の記述）

- 所持ポイントの離散化を四捨五入にすると、約半数の遷移で価値が過大になり、最適化はちょうどその誤差を選ぶ。最初の実装は上限 0.4211 に対し 0.4823 を出しており、離散化の誤差からポイントを「生み出して」いた。切り捨てに直し、到達確率の理論上限 `P(到達) ≤ 最大払戻率 × 初期資金 ÷ 目標` と照合して、超えたら停止する検査を入れた。
- 判断（Python）と送信（Go）を分け、計画ファイルの SHA-256 を両側で照合する。モデルの結論と実際に送った内容が同じだったことを後から確かめるため。
- 誤送信防止のために送信条件を 5 段階＋緊急停止ファイルにした。

## 批判的に読む

- 公開されているのは合成データでの検証だけで、実データでの NLL 改善や大会の収支の内訳は README では分からない（`submission/` の台帳を見れば確かめられる可能性がある）。
- 大会の好成績は 204 レース中 4 的中の結果であり、著者の言うとおり手法の優位性の証拠にはならない。一方、目標到達型の大会では「期待値を上げる」より「分散をいつ取るか」が効く、という構造の指摘は妥当で、大会の順位を手法の良し悪しと混同しないための良い注意書きになっている。
- 動的計画法は他の参加者の動きを考えていない（著者も明記）。順位で決まる大会では、他者の残高分布によって最適な分散の取り方が変わる。

## keiba-ai での使い方

- **市場確率を基準にした正則化**（市場の重み 1・他の重み 0 に引き寄せる）は、モデルが市場から離れることに対価を払わせる設計として、Benter 型の結合モデルの実装にそのまま使える。
- 三連単の控除除去確率と Harville 確率の比較は、「単勝から連系確率を作る」研究の基準実験になる。三連単オッズがあれば Harville は情報を足さない、という合成データでの結果を実データで確かめる価値がある。
- `odds_factor`（賭けた時点のオッズと確定オッズの比）は、直前オッズで判断して確定オッズで払い戻されることの補正として、評価コードに入れるべきパラメータ。実データで比を測定する実験を立てる。
- 到達確率の理論上限との照合や、離散化を保守側に倒す工夫は、資金配分のシミュレーションを書くときのテストの手本になる。
- netkeiba の大会に参加する場合の実装面（ハッシュ照合、送信の多段ガード、追記型ログ）の参考資料として残す。
