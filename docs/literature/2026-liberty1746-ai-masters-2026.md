# LightGBM の1着二値分類＋複勝・ワイド・馬連で学生大会14位 — 回収率113%、オッズは最終週に資金配分だけに使った

> 一言で: 2025年に続いて学生大会（AI競馬予想マスターズ2026）に参加した学生の解説（2026年10月1日）。LightGBM で1着かどうかを二値分類し、出走馬の中での相対的な優位を重視した特徴量を使った。2020〜2025年の中央競馬全レースで学習し、大会提供データに調教師・厩舎情報のスクレイピングを足した。出馬表取得から投票まで自動化。前半は複勝中心で回収率が伸びず、3週目に複勝5：ワイド・馬連5に変え、最終週は複勝をやめてオッズを資金配分に使い、最終ポイント1,133,240pt（回収率約113%、最高150%）、的中率34.19%、117レース、14位。

大会のルールと全体の結果は [2026年学生大会](./2026-netkeiba-ai-masters-2026.md) にまとめた。著者は2025年大会では「ロロ」で12位（787,700pt）だった（[2025年学生大会](./2025-netkeiba-ai-masters-2025.md)）。

## データ

「1、予想AIについて」の節:

- 使用データ期間は2020年〜2025年の中央競馬全レース。
- 大会提供データ（過去30年分の全レースのデータとオッズ）に加え、同期間の調教師・厩舎情報をスクレイピングで用意した。
- 大会は当日出馬表取得 API、リアルタイムオッズ取得 API、投票 API を提供している（「概要」の節）。

## 特徴量

騎手や馬の能力に加え、過去に強かったかだけでなく「今回の出走馬の中でどれくらい優位か」を特に重視したとある。具体的な特徴量の一覧はない。

## モデルと目的変数

- LightGBM の二値分類。目的変数は1着かどうか。
- 試験期間から3週目まではオッズを使わず、勝ちやすさの予測に徹した。最終週だけ、オッズを資金配分に使った（モデルの入力には使っていない）。
- 複勝圏（3着以内）を予測するモデルも作ったが、性能が良くなく補助的な利用にとどめた。

## 運用

起動後、(1) API から出馬表を取得、(2) 投票対象レースを仮選定、(3) 発走10分前に資金配分をして投票、(4) 対象レースがすべて終わったら停止、を自動化した。オッズを最初に使わなかった理由の一つは、提供 API の特性上の安定稼働の課題だったと書いている。

## 賭け方の変遷

「2、試験運用期間・前半2週間の戦略」の節:

- 目標は回収率100%超・的中率30%以上。前年の上位入賞者が全員100万pt超だったため。
- ノルマ（50万pt・96レース）を日割りにして1日12レース・62,500pt。2歳戦と障害レースは除外。1日の初めにレースを品質で分け、高い順に選び、均等割りを基本に品質で金額を変える。
- 券種は複勝で安定させ、ワイド・馬連で回収率を上げる。試験期間は回収率100%超だったが、本番の2週間は下振れが続き最高でも90%程度。

「3、3週目の戦略」の節:

- 問題点として、複勝中心では外れたときに回収できない、ワイド・馬連を1点に絞りすぎて当たらない、的中率は高いのに儲からない（買い方で回収率が下がる）を挙げる。
- 複勝50%・その他50%に変え、ワイド・馬連は本命を軸にした流し・ボックスにして点数と配分は AI に決めさせた。回収率は横ばい。

「4、最終週・最終日の戦略」の節:

- 50万ptの上限を外して資金を多く使い、複勝をやめて馬連・ワイドだけにした。最終週初日に回収率100%に到達し、翌日に最大の的中（約27万pt。9/20 中山8R、馬連1-4 3,100pt とワイド1-4 6,500pt）。最高で回収率150%程度、最終日前日に11位。
- 最終日は回収率100%を割らない範囲で勝負したが回収できず、14位で終えた。

## 結果（「5、まとめ」の節）

最終順位14位、投票117レース、最終ポイント1,133,240pt（最高1,367,620pt）、回収率113%（最高150%）、的中率34.19%。入賞圏はすべて200万pt以上だったとある。オッズと予測確率を使った資金配分で回収率が上がったことを最大の学びとし、最初からリスクを取れば良かったと振り返る。

## 批判的に読む

- モデルの検証（学習・検証の分割、AUC や対数損失などの精度、バックテストの回収率）は書かれていない。次回の記事で成績を深掘りするとある。
- 117レース・約3週間の結果で、回収率113%は最終週の1本の的中（約27万pt）に大きく依存している。
- 試験期間の回収率100%超と本番の90%の差は、期間の短さで十分に説明できる。

## keiba-ai での使い方

- 「モデルにはオッズを入れず、資金配分にだけオッズを使う」構成は、確率モデルと賭け金決定を分ける設計の具体例。[Benter 2019](./2019-benter-model.md) のように大衆確率と結合する方法と比べる対象になる。
- 「的中率は高いのに儲からない」という問題を、券種の組み合わせ（複勝とワイド・馬連の比率）で調整した記録として、keiba-ai の券種別の評価に使える。
