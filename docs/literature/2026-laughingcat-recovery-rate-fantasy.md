# JRA-VAN 全データで AUC 0.821、市場は 0.845。3連複の 120% はリークと緩い的中判定だった

> 一言で: JRA-VAN Data Lab の 1954年以降 137,331 レース・1,836,466 頭走で LightGBM を作った個人の2か月の記録。バックテストの「3連複フォーメーションで回収率120%」は、過去成績の集計にそのレース自身の結果が混ざったリークと、買っていない組み合わせまで的中に数える判定のバグによるもので、直すと 83%。現在の勝ち馬判別 AUC はモデル 0.821、市場（オッズ）0.845。ライブ運用 328 レースで 3連複 12点の回収率 70.2%。

#1 は無料で2026年8月17日公開。#2（技術編）・#3（評価の統計）・#4（定説の検証）は有料で、#2・#3 は無料部分だけを添付として保存した（有料部分は取得していない）。

## データ

「データ編」の節。

- 最初はウェブから約 3,900 レースをスクレイピングしたが、全 JRA レースの 3% 程度で、重要な特徴量の 53% が欠損していた。
- JRA-VAN Data Lab に切り替え、1954年からの 137,331 レース、1,836,466 頭走を取得。1行 555 バイトの固定長 Shift-JIS をバイト位置で解析した。
- データを差し替えただけで勝ち馬判別の AUC が 0.719 → 0.775 に上がった。著者は「2ヶ月の開発で最大の改善は、モデルの工夫ではなくデータの入れ替え」と書いている。

## 特徴量・モデル

- 特徴量は 96 個（#2 の無料部分の目次）。中身は有料部分なので未確認。
- #2 の目次によると、構成は勝率・複勝率・順位学習の3モデル＋較正＋期待値モデルの分業。
- 最初は着順の回帰モデル。的中率は出るが回収率は大幅マイナスで、調べるとモデルは人気馬を上から並べていただけだった（「モデル編」の節）。そこで「当てるAI」から「オッズと実力のズレを探すAI」に設計を変えた。

## バグの記録

「バグ編」の節。どれも表面上は普通に動いていた。

- **脚質**: コーナー通過順を頭数で割るべきところを馬番で割っていて、出走馬の 78% が追込馬と判定されていた。その上に展開予想が載っていた。
- **母父**: 血統データのバイト位置の読み違いで、母父の列に別の祖先が入っていた。修正後、ある種牡馬の産駒の母父が 1 種類から 398 種類になった。
- **馬体重 0kg**: 朝の予測時点では当日の馬体重が未発表なので、欠損を 0 で埋めていた。

## リークと評価のバグ

「リーク編」の節。

- バックテストでは「3連複フォーメーション（11点買い）で回収率 120%」、本命の複勝率 64〜67%。
- 原因1: 過去成績の集計処理に、そのレース自身の結果が混ざっていた。
- 原因2: 的中判定が緩く、実際には買っていない組み合わせまで的中に数えていた。その配当は買い目内の配当より2倍以上高かった。
- 直したうえで「実際に買う12点だけを的中と数える」判定でやり直すと、回収率 83%、本命の複勝率 60.5%。この複勝率がライブ実測（週次 57〜64%）と初めて一致した。
- さらに外部の AI エージェントにコードを審査させると、まだ3箇所のリークがあり「モデルの実力の約 9% は偽物」と判定された（修正済み）。

## 結果（現在地）

「現在地」の節。

| 指標 | 値 |
|---|---|
| 勝ち馬判別 AUC | モデル 0.821、市場（オッズ）0.845 |
| オッズ同水準の馬どうしで、AI 上位評価の馬の単勝 | 回収率 +13 ポイント（著者は統計的に有意と書く。検定方法は無料部分に書かれていない） |
| ライブ運用 328 レース、3連複 12点 | 的中率 31.4%、回収率 70.2% |
| AI が「自信あり」としたレースに限定（75 レース） | 回収率 87.5% |
| 参考: 全出走馬の単勝を均等買い | 約 72% |

著者のまとめは「AI の上乗せは実在するが、控除率の壁はまだ越えられていない」。

## #3 の論点（無料部分）

#3 は「リークを全部直したあとに残る問題」として、評価の統計を扱う。無料部分で示されている論点は次のとおり。

- 手元の検証データで回収率の差をどこまで見分けられるか（検出力）。著者は、当時のバックテストで 110% が出ていても「勝てるモデルができた」と判断するのは誤りだった、と書いている。
- 条件を探し回ると、実力がゼロでも 100% を超える仕組み（多重比較）。
- やめる条件も含めて、実験前に判定基準を固定する運用。
- ライブと机上が食い違ったときにどちらを信じるか。
- 外部レビューや自動ゲートで自分の数字を疑う仕組み。

具体的な数値は有料部分にあり、このノートでは確認していない。

## 落とし穴と教訓

- データの網羅性（欠損率）が精度の上限を決める。スクレイピングで集めた一部のレースでは、過去成績の特徴量が穴だらけになる。
- 回帰で着順を当てにいくと人気順を再現するだけになる。市場とのズレを目的にしないと回収率は上がらない。
- 的中判定のコードは、買い目の集合と払戻の組み合わせを厳密に突き合わせる。緩い判定は高配当側に偏って誤る。
- バックテストとライブの指標（本命の複勝率など）が一致するかを、リークの検出に使える。

## 批判的に読む

- 現在地の数字は市場の AUC を下回っており、回収率も 100% 未満。著者自身が勝てていないと明言しているので、誇張は少ない。
- 「同オッズ帯で +13 ポイント」は、条件で切った比較なので多重比較の影響を受けやすい。著者が #3 で扱っている問題そのもの。
- 「自信あり」75 レースで 87.5% は、標本が少なく誤差が大きいと著者も書いている。
- 分割方法（学習・検証の期間）は無料部分には書かれていない。

## keiba-ai での使い方

- 評価に「市場（オッズから逆算した確率）の AUC・logloss」を必ず並べ、モデル単体の数字だけで判断しない。
- 「オッズ同水準の馬どうしでモデル上位を買うと回収率が上がるか」という比較は、市場に対する付加価値を測るよい切り口。オッズ帯で層別した回収率を評価に入れる。
- 的中判定は「実際に買った組み合わせ」と払戻の組み合わせを厳密に照合する関数を `src/keiba_ai/` に1つだけ置き、テストを書く。
- 予測時点で未発表の値（当日馬体重）は 0 埋めせず欠損として扱う。脚質など派生特徴量の分布をサニティチェックする（追込 78% のような偏りを検出する）。
- 回収率の差を主張する前に、検証レース数で検出できる差の大きさ（検出力）を計算しておく。
