# JRDB 24年分で3着内を正解率 81%、複勝を全部買うと「すごいマイナス」

> 一言で: JRDB の KYI（前日の競走馬データ）・SED（成績）・HJC（払戻）を 1999〜2022 年分ダウンロードし、KYI に過去5走の SED を横結合して、LightGBM で3着以内を二値分類した。正解率 0.81 だが、全部「4着以下」と言うだけで 0.78 になる。「3着内」と予想した馬の複勝を 100 円ずつ買うと累積利益は大きなマイナスだった（金額は書かれていない）。

2023年12月24日公開（DMM WEBCAMP Advent Calendar 2023）。記事本文は初心者向けの手順説明で、コードは GitHub（sf-12/uma-ai-jrdb）のノートブックにある。分割方法と出力はノートブックで確認した（attach: `notebook-04-merge-data`、`notebook-05-target-features`、`notebook-06-learn-model`、`notebook-07-predict-test`）。JRDB の固定長ファイルを読む手順と、「正解率は高いが複勝で負ける」例として読む。

## データ

- JRDB（有料会員）の年度パック。KYI・SED・HJC を 1999〜2022 年分（「データのダウンロード」の節）。
- 仕様書（kyi_doc.txt など）に従って固定長テキストをバイト位置で切り、JSON にまとめたフォーマット定義で一括変換する（「02. データをフォーマットする」の節）。不要そうな列はこの段階で落とした。
- KYI の「前走1〜5競走成績キー」で SED を5回結合し、過去5走の成績を横に並べる（「04. データを結合する」の節）。当該レースの SED からは着順だけを結合している（ノートブック 04 で確認）。
- テストが 234,242 行で全体の 20% なので、全体はおよそ 117 万行（ノート作成者の計算）。

## 特徴量

- 結合後の数値型の列を自動で全部「説明変数」にし、object 型の列は使わない（「05. 目的変数と説明変数を抽出する」の節）。列の用途は JSON（usage: target / feature / key / null）で管理し、手で直せる。
- 中身は、KYI の IDM・騎手指数・情報指数・激走指数・万券指数・基準人気順位・上昇度・厩舎評価などの JRDB 独自指数と、過去5走の SED（JRDB の上昇度コード・テン指数・上がり指数・馬ペース・10時複勝オッズ・斤量など）。
- 騎手名・調教師名などの文字列は使っていない（改善案に「騎手や調教師の情報も使ってみる」とある）。

## モデルと目的変数

- 目的変数は「3着以内」（着順 ≤ 3 なら1）。「1着」の列も作ったが使っていない。
- `LGBMClassifier`。`GridSearchCV`（num_leaves 30/50/100、learning_rate 0.1/0.05/0.01、n_estimators 100/200/500 の 27 通り、5分割 CV、scoring='accuracy'）で、最良は learning_rate 0.05・n_estimators 500・num_leaves 50。CV の正解率は約 0.809。

## 評価

- 分割は `train_test_split(test_size=0.2, random_state=42)` の行単位のランダム分割（ノートブック 06）。時系列でもレース単位でもない。
- 指標は正解率と classification_report。
- 収支は、モデルが「3着内」と言った馬すべてに複勝 100 円。HJC の複勝払戻（確定）から利益を出し、テストの行順に累積利益をグラフにした。回収率の数値は出していない。

## 結果

- テストの正解率 0.810。クラス1（3着内）の適合率 0.65、再現率 0.33、F1 0.44。クラス0 は 182,131 行、クラス1 は 52,111 行（ノートブック 07 の出力）。
- 全部を「4着以下」と予測した場合の正解率は 182,131 / 234,242 = 0.778（ノート作成者の計算）で、モデルの上積みは約 3 ポイント。
- 複勝の累積利益は「すごいマイナス」（「馬券を買った場合の利益を調べる」の節）。的中しても 100 円が 130 円になる程度で、外れの −100 円を取り返せない、と著者は説明している。
- 特徴量重要度（分割回数）の上位は「SED_3走前_上昇度コード」994 など過去5走の上昇度コードが並ぶ、と記事は書く。ただし下の「批判的に読む」のとおり、名前の対応がずれている可能性が高い。

## 落とし穴と教訓

- 正解率 80% 超でも、配当の低い人気馬に偏った複勝ではプラスにならない。著者自身が「的中できるモデル」と「利益の出るモデル」は別だと結論している。
- JRDB の固定長ファイルは、フォーマット定義を JSON にしてコードで切るのが現実的。

## 批判的に読む

- 行単位のランダム分割なので、同じレースの馬が学習とテストに分かれ、未来のレースで過去を予測する形にもなる。時系列分割なら正解率はもう少し下がるはず。
- 特徴量重要度の名前がずれている。学習は `KYI_レースキー` を落とした列で行っているのに、重要度の表示には落とす前の `X_train.columns` を使っている（ノートブック 06 の 06.3.4）。レースキーは列の先頭なので、表示名はすべて1列ずつ前にずれる。学習していないはずの「KYI_レースキー: 219」が重要度に出ているのがその証拠。「上昇度コードが効いている」という記事の読みは、実際には隣の列の重要度である可能性が高い。
- 当該レースの SED からは着順だけを結合しており、確定オッズやタイムなど当日以降の情報は入っていない。KYI は前日データで、JRDB の指数（IDM、激走指数など）もレース前に配信されるものなので、特徴量の時点としては大きなリークは見当たらない。ただし KYI の年度パックが「前日版」か「当日更新後」かは確認していない。
- 二値分類の閾値 0.5 で「3着内」と言った馬を全部買うので、1レースの点数がばらばらになる。回収率・的中数・点数を出していないので、マイナスの大きさも比較できない。
- 複勝払戻の計算は、予想馬の馬番が複勝払戻1〜3のどれにも一致しないと None を返す。同着などで4頭目の払戻があるケースは落ちる（件数は少ない）。

## keiba-ai での使い方

- 二値分類の正解率は「全部0」の基準値（ここでは 0.778）と並べて報告する。主指標は対数損失・Brier と、控除率込みの回収率。
- 特徴量重要度を出すときは、学習に渡した DataFrame の列名をそのまま使う（`model.feature_name_` を使う）。列を落としてから学習する処理を挟むときの単体テストを書く。
- JRDB を使う場合は、KYI/SED/HJC のフォーマット定義を JSON で持つ方式を参考にし、`data/raw/` に年度パックを不変で置く。KYI の配信時点（前日・当日）を `data_version` に記録する。
- 複勝で買うなら、3着内確率と複勝オッズ（の推定）から期待値を出して買う馬を絞る。確率 0.5 を閾値にして全部買う設計は避ける。
