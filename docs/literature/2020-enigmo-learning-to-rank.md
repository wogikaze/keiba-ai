# 2か月分のデータで LGBMRanker を学習し、人気順買いと「必勝本」に勝ったかを比べた短期実験

> 一言で: netkeiba からスクレイピングした約2か月（540レース）の出馬表＋単勝オッズで LightGBM の lambdarank を学習し、予測上位を単勝・3連複・3連単で買った。検証（252レース）は合計回収率 68.44%（人気順 53.07%）、テスト（48レース）は 110.56%（人気順 78.54%）。ランク学習の最小実装としては参考になるが、オッズは確定後の値で、期間も極端に短い。

社内アドベントカレンダーの1本で、3日目の同僚の記事（竹本「競馬必勝本は本当に当たるのかを検証！」、attach 済み）の続編として書かれた。著者は競馬は「ズブの素人」と書いている（冒頭）。

## データ

- netkeiba の出馬表・単勝オッズ・結果ページを 1 秒間隔でスクレイピング（「データ取得」の節）。オッズページは Selenium で描画して取る。
- 期間（JRA）:
  - 訓練 2020/09/05〜10/31（540レース）
  - 検証 2020/11/01〜11/23（252レース）
  - テスト 2020/11/28〜11/29（48レース）
- 払戻（単勝・3連複・3連単）は結果ページから取得。3着以内に同着がある場合は最初のパターンだけ取る（脚注3）。

## 特徴量

- 出馬表: 馬番、枠、馬名、斤量、騎手、厩舎、馬体重と増減、年齢、性別。カテゴリは category_encoders の OrdinalEncoder（馬名・騎手・厩舎・性別）。
- オッズ由来（`add_features`）: レース内最小オッズとの差 `odds_diff`、比 `odds_ratio`、オッズの偏差値 `odds_deviation`、斤量＋馬体重 `all_weight`。
- 過去成績の特徴量はない。特徴量重要度ではオッズ関連が上位だった（「学習」の節）。

## モデルと目的変数

- LightGBM の `LGBMRanker`、objective は lambdarank、metric は NDCG@1,2,3。learning_rate 0.01、num_leaves 31、early stopping 50（「学習」の節）。
- ラベルは着順を反転した値（最下位=1、1着=頭数）。失格は 20 着扱い、中止・除外・取消は除外。
- レースを query（group）として渡す。

学習結果: 訓練 NDCG@1 0.550、検証 NDCG@1 0.444・@3 0.551。

## 評価と賭け方

- 各レースで予測1位の単勝、上位3頭の3連複、上位3頭を順序どおりの3連単を、それぞれ 100 円ずつ全レースで買う。
- 比較対象は「オッズの低い順」に同じ買い方をした場合（人気順ベースライン）。
- 回収率は結果ページの払戻金で計算。合計回収率は3券種の合算。

## 結果

「VSオッズ低い順」の節:

| データ | 方式 | 単勝 的中率 / 損益 | 3連複 的中率 / 損益 | 3連単 的中率 / 損益 | 合計回収率 |
|---|---|---|---|---|---|
| 検証 252R | LightGBM | 30.95% / +4,660 | 6.75% / −11,460 | 1.59% / −17,060 | 68.44% |
| 検証 252R | 人気順 | 32.14% / +2,450 | 5.56% / −15,660 | 0.40% / −22,270 | 53.07% |
| テスト 48R | LightGBM | 37.50% / +1,360 | 14.58% / +1,060 | 4.17% / −900 | 110.56% |
| テスト 48R | 人気順 | 37.50% / +1,310 | 12.50% / −1,040 | 2.08% / −3,360 | 78.54% |

ノート作成者の計算では、検証の単勝回収率は LightGBM 約 118%、人気順 約 110%。1番人気の単勝を買い続けて 110% は長期平均（概ね 80% 前後）から大きく外れており、この3週間がたまたま本命が強かった期間だったことを示す。

「VS競馬必勝本」の節: 検証期間の3連複だけで比べると、LightGBM 全レース −11,460 円、必勝本の条件 −14,630 円、人気順 −15,660 円。著者は「まぐれかもしれない」と断っている。

## 落とし穴と教訓（著者の記述）

- 脚注2で、正しく比較するにはテストを検証と同じ期間（11/1〜11/23）にすべきだったと書いている。必勝本との比較は検証期間で行っている。
- 「なかなか簡単には儲かりませんね」（感想）。次の課題として、コース・天気・血統、データ期間の延長、賭けるレースの選別、券種の選択を挙げる。

## 批判的に読む

- オッズは結果確定後にオッズページから取得した値、つまり確定オッズ。馬体重も当日発表の値。実際に買える時点のオッズとの差は検討されていない。同僚の記事は、検証では最終オッズを使い、実戦は 10:30 時点のオッズで選ぶと明記している。
- `odds_deviation` はレース内ではなくデータセット全体の平均・標準偏差で標準化している。テストに対してはテスト内の統計を使うので、テスト期間全体の情報がわずかに混ざる（影響は小さいが、レース単位で閉じた特徴にすべき）。
- 訓練2か月・テスト2日。48 レースでの 110% は、3連複の数本の的中で決まる。検証期間（252レース）では 68% で、人気順より良いという結論の方が頑健。
- 馬名を OrdinalEncoder で数値化して入れているが、2か月で同じ馬が何度も走ることは少なく、ほぼノイズになる。
- 3連単を「予測上位3頭の順序どおり」の1点だけ買うのは、ランキングの評価としては意味があるが、賭け方としては期待値を見ていない。

## keiba-ai での使い方

- LightGBM の lambdarank を `group=` でレース単位に渡す最小の実装例として参照できる。ラベルを「頭数 − 着順 + 1」とする変換と、失格・中止の扱いは決め事として ADR に書く。
- 人気順（オッズの低い順）を同じ買い方で回したベースラインを必ず並べる。この記事のように、検証期間の人気順が 110% になる期間もあるので、モデルの回収率は人気順との差で見る。
- オッズを特徴量に使うなら、取得時刻（確定か、発走何分前か）を列として持ち、確定オッズでの評価は参考値として分ける。
