# 自作の競馬予想MLで効率的市場仮説に挑んで、跳ね返された話（umascore 2026）

> 一言で: 6成分（うち1つがオッズ由来）の合算スコアを softmax で勝率にする自作モデルから、オッズ成分を抜く ablation を行った。バックテスト（BT）ではオッズ成分を抜いても回収率 116.7% と崩れなかったが、フォワードテスト（FT）では抜いた版が 49.3%、入れた版が 64.5% だった。前向きに効いていたのは市場側で、自作のファンダメンタル5因子にはオッズと独立した前向きのエッジがなかった。地方競馬（NAR）でも同じ結論が出た（添付の第4本）。

連載の第3本。第1本（リーク対策、添付 `race-date-leak`）、第2本（BT 118% → FT 40%台の劣化の分解、別ノート [umascore 2026](./2026-umascore-backtest-forward-decay.md)）、第4本（NAR の walk-forward、添付 `chihou-walk-forward`）とつながる。

## データ

- JRA 中央競馬。BT は 16か月（2025-01〜2026-04）、FT は 2026-04 以降の約6週（「3.2 結果」の表）。
- 入手元の詳細は本記事にはない。第1本によれば Python + SQLite のパイプラインで、過去走・血統・コース実績を自前の DB に持つ。
- 第4本（NAR）: 南関4場と園田・高知、2025-01〜2026-04 の 7,960 レース、86,246 出走。過去5走以上の履歴がある馬は 50.7%。

## 特徴量

学習ではなく手で重みを決めた合算スコア `master_score`（0〜100点）を使う（「2. モデル設計の最小スケッチ」）。

| 成分 | 点数幅 | 中身 |
| --- | --- | --- |
| base_adjusted | 0–35 | 過去走タイム・着差・対戦比較 |
| bias_adjusted | 0–10 | トラックバイアス補正 |
| training_score | 0–15 | 調教評価 |
| aptitude_score | 0–15 | コース・距離・馬場適性 |
| human_factor | 0–10 | 騎手・厩舎・斤量 |
| odds_implied | 0–15 | 1/odds から算出 |

副次的な発見として、トラックバイアスは本番でデータが来ず全頭デフォルト値（Cohen's d = 0.065）、調教もほぼ全頭デフォルト（d = 0.037）で、2成分は事実上死んでいた（「6. 副次発見」）。

第1本のリーク対策: 過去走集計・コース適性集計・**血統経由の集計（種牡馬産駒の同条件成績を JOIN で取るクエリ）**・推論時の呼び出しの4経路すべてに `race_date < ?` を入れる。著者は、コース実績の集計でフィルタを入れたため、後段の血統フォールバックのクエリもフィルタ済みと錯覚した点がいちばん見落としやすかったと書く。

## モデルと目的変数

- レース内で `softmax(master_score / 5.0)` を取り勝率とする。学習は行わない（温度 5.0 は手で決めた値）。
- EV = 勝率 × オッズ を計算し、EV ≥ 1.5 の単勝を買う。
- 第4本では同じルール（M1）と LightGBM（M2）を比べた。

## 評価

- BT: 16か月の単勝 EV≥1.5。使うオッズはコード上 `final_odds`（確定オッズ）。
- FT: 実投票ではなく、記録したスナップショットでの集計（「8. 補足」）。どの時点のオッズかは本記事では明記されていない。
- ablation: 同じパイプラインで `odds_implied` を 0 にして softmax を再計算する。大穴が混じって高分散になるのを避けるため、「全件」と「odds ≤ 20」の2系統で集計する。
- 第4本（NAR）: 月次ローリングの walk-forward。テストは 2025-07〜2026-04 の10か月で、各月の前の全データで学習する。比較の基準は「1番人気を買い続ける」M0。

## 結果

「3.2 結果」の表:

| 版 | BT 16か月 | FT 6週 |
| --- | --- | --- |
| WITH（全成分） | n=4,835 / 的中 15.3% / 116.3% | n=580 / 8.8% / 41.2% |
| ABLATED 全件 | n=24,705 / 2.8% / 81.8% | n=2,633 / 1.6% / 60.1% |
| WITH & odds≤20 | n=3,601 / 19.9% / 102.7% | n=370 / 13.8% / 64.5% |
| ABLATED & odds≤20 | n=3,251 / 13.2% / 116.7% | n=336 / 6.0% / 49.3% |

- BT ではオッズ成分を抜いた方が良く見えた（116.7% > 102.7%）。FT では逆転し、的中率の差は2倍以上になった。著者は「BT の最良が FT で崩れる、過学習の教科書的な症状」と読む。
- `corr(master_score, 1/odds) = 0.78`。著者は、オッズを写しているのではなく、同じ公開情報を別の経路で読んだ結果として寄ったと解釈する（「4. 検証2」）。
- 未使用の馬体重増減（weight_diff）を単勝 3〜7倍帯に絞って5つのバンドで見ると、勝率は 16.7〜17.7% でほぼ平坦だった（「5. 検証3」）。
- 過去に死に成分の重みを0にして再配分したところ、相対的にオッズ成分の比率が上がり、BT 回収率は 118% → 93% 台になった。
- 第4本（NAR、10か月 OOS）: 全頭に単勝を買うと 70.3%、1番人気を買い続けると 81.2〜82.0%。M1 の EV≥1.5 は 100.6%（n=5,424）、LightGBM の M2 は本命が 84.3%、EV≥1.5 が 69.0%。地方は市場が小さいので非効率だという仮説も、園田・高知で M1 102.4%、M2 EV≥1.5 47.0% となり、支持されなかった。

## 落とし穴と教訓

- **ablation は in-sample と out-of-sample の両方で見る。** in-sample だけでは「市場成分は希釈要因」という逆の結論になる。
- 自分のスコアと市場の確率が高く相関していることだけでは、写しているのか同じ情報を読んでいるのかを区別できない。前向きの ablation と組み合わせて初めて意味が出る。
- 使っていない構造化データも、オッズ帯で統制すると勝率の勾配が消える。
- フォールバックのコード経路（血統で推定する分岐など）にも同じ時点フィルタが入っているかを、独立に点検する。

## 批判的に読む

- BT の EV は確定オッズで計算している。買う時点のオッズとの差（[yurelu 2026](./2026-yurelu-v11-distribution-shift.md) の T-10/T-2 問題）があり、BT の 116% は実際に買える値より楽観的な可能性がある。FT 側で使ったオッズの時点も書かれていない。
- FT は約6週・数百点しかない。WITH と ABLATED の差（64.5% と 49.3%）も、回収率の信頼区間を出していない。的中率の差は大きいので、方向はおそらく正しい。
- softmax の温度 5.0、EV ≥ 1.5、odds ≤ 20 の切り方は事後の選択で、複数の切り口を見ている。
- 学習していない手製スコアなので、「ML がオッズに勝てない」の証拠としては弱い。ただし第4本では LightGBM でも同じ結論だった。
- NAR の全頭単勝が 70.3% で、控除率から期待される 75% を下回る。著者は丸めや欠損で説明しているが、払戻データの欠け方に偏りがないかは未確認。

## keiba-ai での使い方

- **市場成分の ablation を評価の定番にする。** オッズ（あるいは市場確率の logit）を入れたモデルと抜いたモデルを、時系列の hold-out と前向きの期間の両方で比べる。Benter の2段階モデル（[Benter 2019](./2019-benter-model.md)）の「ファンダメンタルが市場に上乗せする情報」を測る手順と同じ。
- ベースラインに「1番人気を買い続ける」「全頭買い」の回収率を必ず並べる。NAR の 81〜82%、70% という水準は比較に使える。
- 未使用の特徴を追加する前に、オッズ帯で統制した勝率勾配を見る。平坦なら市場が織り込み済みとして優先度を下げる。
- 特徴量生成の SQL・pandas コードに、`race_date < 対象日` を全経路で強制するテスト（フォールバック経路を含む）を入れる。
