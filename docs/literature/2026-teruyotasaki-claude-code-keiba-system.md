> 一言で: JRA・地方（NAR）・ばんえいを対象に、スクレイピングから LightGBM 予測、自動投票（地方は Playwright、中央は IPAT）、日次レビューまでを個人で運用する記録（2026年8〜11月、全11回）。回路別にモデルを分けると AUC が改善した。一方で、グリッドサーチで選んだ買い目フィルタは walk-forward で JRA 188.3%→26.0%、NAR 115.4%→94.0% に崩れた。地方競馬のサイト側 HTML 変更で主要列が静かに欠損し、AUC が週ごとに悪化した事故の記録が具体的。

各回は `library/2026-teruyotasaki-claude-code-keiba-system/attachments/` に保存（第2〜11回）。以下「第n回」。

## データ

- 競馬情報サイト（名称は伏せている）からレース結果・払戻・馬／騎手／調教師マスタ（5代血統を含む）・出馬表・オッズをスクレイピングし、SQLite に登録（第2回）。
- マスタは最終更新から30日経過したものだけ再取得。地方は結果ページの構造が違うので専用経路。
- オッズは発走 120 分前・30 分前の定点観測をレース単位の CSV に追記（第7回）。

## 特徴量

- 近走成績・距離・馬場などの基本に、5代血統、騎手×競馬場・調教師×競馬場・馬×競馬場のコンビ成績、JRA と地方の移籍方向と競馬場ティアの変動、騎手による脚質の出方、ばんえい固有の体重関連（第3回）。
- Target Encoding、年次重み付け（今年 1.0、去年 0.7、一昨年 0.5）。初出走は中立値・中位値・全体平均でフォールバック。
- 特徴量数は JRA/NAR が 170、ばんえいが 175。
- 市場特徴量（オッズ・人気）を入れたモデルと入れないモデルを比較した（第7回、数値なし）。

## モデルと目的変数

- LightGBM。初期は3着以内確率、のちに is_win。NAR では is_top3 に切り替えて全的中率が 10.6%→21.8%（第6回）。is_top3 の確率をそのまま単勝 EV に使うと計算が破綻する、と注意している。
- JRA / NAR / ばんえいで回路別にモデルを分離し、AUC が改善（第3回、数値なし）。
- 学習窓を 13 か月学習＋13 か月検証から 4 か月学習へ短縮。NAR は日次、JRA とばんえいは週次で再学習。
- 第10回: 本番モデル A と候補モデル B の A/B 並走（B は A と一致したときの後押しのみ）、券種ごとのメタモデル（見送り判定）、三連複配当の対数を予測する「荒れやすさ」モデル。

## 評価

- EV（予測確率×オッズ）閾値と Kelly 基準のバンクロール管理、券種別の1日予算上限（第4回）。
- グリッドサーチ（EV 閾値・確率閾値・エントロピーの3軸）で見つけた条件を、walk-forward（学習期間とは別の未見期間）で検証。
- 日次でAUC・LogLoss の推移と戦略別 ROI を Notebook で確認（第11回）。払戻は DB の実際の払戻で全券種を計算。

## 結果

- グリッドサーチ条件の walk-forward 検証（第4回）: JRA 学習期間 ROI 188.3% → 未見期間平均 26.0%、NAR 115.4% → 94.0%。
- 実運用: 日単位では ROI 100% 超の日があるが、週・月単位では 100% を超えたことがない（第4回）。
- 穴馬狙い（人気薄なのに予測確率が高い馬）は walk-forward で振るわず、人気馬に絞るほど ROI が単調に改善した（第6回、第8回）。複勝人気馬戦略は単勝オッズ軸でほぼ収支ゼロ、予測確率軸で一貫して損失。
- オッズ変化（120 分前→直前）と着順の相関は 0.12 程度で弱いシグナル（第7回）。
- 1〜3番人気の予測ハズレ率は 26% 程度で、人気薄ほどハズレ率が高い（第8回）。同じモデルの的中率は NAR のほうが JRA より2〜3倍高い。
- コンセンサスフィルター（ランカーと従来モデルが一致したレースだけ買う）はバックテスト 113.5% だったが、リークを取り除いて月別に見直すと中央で4か月連続 51〜76%（第10回）。無効化した。
- 券種別メタモデルのフィルタは、効果が継続的に100%を超えないため閾値ゼロ（無効）で運用（第10回）。

## 落とし穴と教訓

- **データ収集の静かな壊れ**（第2回、第9回）: 地方競馬の AUC が 0.80 から週ごとに悪化。学習データの行数は変わっておらず、情報源の HTML 構造変更で馬名・馬 ID・騎手・調教師・オッズ・人気の列が取れていなかった。再学習のたびに欠損データが積み上がった。パース後の主要列の欠損率チェックを導入。
- 日次レビューの HTML レポートで前走レース列が空の馬が大量にいることに気づき、地方 2,000 件超のレースをアーカイブ HTML の再パースで修復、残り約 400 件は再取得（第11回）。
- グリッドサーチで見つけた閾値は walk-forward で検証するまで信用しない。
- 複数モデルを組み合わせるときは、各モデルの学習期間と評価期間の重なりを確認する（第10回）。
- AI（Claude Code）の出した良い結果を、未見期間で検証せず本番に入れない（第9回）。

## 批判的に読む

- AUC、ROI の多くは数値が出ておらず（回路分離の改善幅、市場特徴量の効果など）、定性的な報告が中心。
- walk-forward の窓の長さ、未見期間の長さ、点数が書かれておらず、188.3%→26.0% の劣化の大きさを評価しにくい。
- 回収率の計算に使うオッズが購入時点か確定かが明記されていない。自動投票の実績と比較すれば判定できるはずだが、記事には出ていない。
- 「地方は市場効率が低い」は NAR の的中率の高さからの推測で、地方の回収率で示されたわけではない。的中率が高いのは頭数・人気の構造の違いでも説明できる。

## keiba-ai での使い方

- 取得パイプラインに「主要列の欠損率」「1レースあたりの行数」の閾値チェックを入れ、閾値を超えたら学習を止める。AUC の時系列監視も併用する。
- JRA と地方を混ぜずに回路別に学習する設計は、地方競馬を扱うときの初期設定にする。
- オッズの定点観測（120 分前・30 分前など）を蓄積しておけば、購入時点オッズでのバックテストに使える。
- 「グリッドサーチで選んだ条件」と「未見期間での成績」を必ずペアで記録する。
