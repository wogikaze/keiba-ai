# トラッキングデータからレースをコマ単位で生成する：前進と横移動のベイズモデルとスリップストリーム

> 一言で: NYRA の 2019 年1マイル戦の位置データ（約4フレーム/秒）で、各馬の「次のフレームでの前進距離」と「横移動距離」を正規分布で別々にモデル化し、フレームごとに交互にシミュレーションしてレース全体を生成する。馬ごとの速度プロファイルを B スプライン、騎手・競馬場をランダム効果、空気抵抗の減少（ドラフティング）を流体シミュレーションから作った共変量で表し、レース中の動的な着順確率や枠の反実仮想実験を示した (pp.6-19)。

原本は arXiv v3（2024年3月、24ページ）。JQAS 20(4) 365-383（2024）に掲載された（DOI 10.1515/jqas-2023-0091、OpenAlex で確認）。掲載版との差は未確認。ページは arXiv 版のもの。

## 問題意識

順位や走破タイムのようなレース単位の結果で学習するモデルは、レース中の戦略（先行するか控えるか、他馬の後ろにつけるか）と能力を区別できない。強い馬同士が同じレースに出やすく、戦略も相手によって変わるので、レース単位の推定は交絡しやすい (p.1)。
既存の多者競技モデル（順位ロジット、[Glickman 2015](./2015-glickman-stochastic-rank-ordered-logit.md) の動的版）は順位しか生成できず、位置を生成できない。本論文は Glickman and Che の「連続的な結果を変換して動的線形モデルで扱う」枠組みをフレーム単位に拡張する (p.2)。

## モデル

各フレーム $i$ の移動を、内ラチに垂直な**前進距離** $\tilde y^{for}_i$ と、内外方向の**横移動距離** $\tilde y^{lat}_i$ に分解する。1マイル戦は前進距離の累計が1マイルに達したら完走 (p.3)。座標をこう変換すると、横方向の位置が「何頭分外を回っているか」として一貫して定義できる。

能力はレース中の位置（累積距離 $j$）で変わる関数 $\theta(j)$ とし、少数の基底パラメータで表す (p.4)。

### 前進モデル

$$\tilde y^{for}_i(k)\sim N\big(\theta_k(j)+\delta_{jockey}+\delta_{track}+X^{for}_i\psi_x,\ \sigma_f\big)$$

- $\theta_k(j)$: 馬 $k$ の3次 B スプライン（内部ノット 90, 250, 800, 1207, 1375 m、境界 0 と 1650 m）。ノット数と位置は簡略モデルの LOO-CV 近似と目視で決めた (pp.11, 17-18)。ノットの位置は発馬後の加速終了や最後の 1/4 マイルなど、戦略の切り替わりに対応する。
- スプラインの係数、騎手効果、競馬場効果はランダム効果で縮小する。スプラインはその区間の平均速度へ、騎手・競馬場は 0 へ (p.11, 式7)。
- 推定は RStan の最適化（MAP）。MAP では裾の振る舞いが悪く非現実的なシミュレーションになることがあり、数頭の反実仮想では部分データで完全な MCMC を回し、前進距離を 0 以上に切断した (p.11)。

### 横移動モデル

同じく正規分布。最も重要な共変量は前フレームの横移動（外へ動いている馬はそのまま動き続ける）(p.12, 式8)。予備的な検討で、横移動の分散の 99% 超は単純な空間共変量、一定の騎手効果、コーナー・直線の区分、前フレームの動きで説明できたので、馬ごとの時間変化する効果は入れていない (p.11)。

前進と横移動は独立と仮定する。フレームが 0.25 秒と短く、前フレームの情報で大部分の依存が説明できるため、と正当化する (p.10)。

### ドラフティング（スリップストリーム）共変量

Blender と OpenFOAM で馬と騎手の 3D モデルの流体シミュレーションを行い、後続馬が 2, 3.5, 5 m 後方・真後ろまたは左右 0.5 m の 3×3 の格子と「きれいな空気」で抗力係数を求め、線形補間する (pp.9-10)。
これから (1) 現在ドラフティングしているかの指標、(2) レース開始からの省エネルギー割合（$E=F_d s$、$F_d=\tfrac12\rho v^2 c_d A$、前面積 $A=1\,\mathrm{m}^2$ と仮定）の2つの共変量を作る (p.10)。

### シミュレーション

全馬について、前進 → 横移動 → 空間共変量の更新、をフレームごとに繰り返す (p.12, Fig.5a)。1マイル戦は約 100 秒、約 400 フレーム。6頭・2,000 事後サンプルで $6\times2\times400\times2000=9.6\times10^6$ 回の正規乱数が要る。Stan の generated quantities を C++ で直接回して、1レース 2,000 回のシミュレーションが 16 コアの MacBook Pro で 90〜120 秒（素の R では 50 回未満に5〜10分）(p.12)。

## データ

Kaggle Big Data Derby 2022（NYRA・NYTHA 提供）の、2019 年の Aqueduct、Belmont Park、Saratoga の全レースの位置データ（緯度経度、約4フレーム/秒）(p.6)。モデルには**1マイル戦だけ**を使う (p.10)。レース数・頭数は本文に明記がない（未確認）。
前処理として、Google Earth からコースの外形とゴール線を取り、直交座標に変換し、直線・コーナーに区分し、欠損や飛びのあるフレームを補完した。1マイル戦の 4.2% の馬で最初の 40 フレーム（約 10 秒）を補完している (pp.6-8)。

## 結果

- **動的な着順確率**: 任意のフレームから残りを繰り返しシミュレーションし、着順ごとの確率をヒートマップで示す。2019年5月16日 Belmont 第3レースの例では、前半5〜7番手で他馬の後ろにいた馬に高い上位確率を与え、実際に2着だった (pp.15-16, Fig.6)。
- **騎手の評価**: 前進モデルの騎手ランダム効果の上位 10 人を、2022 年の各競馬場の賞金ランキングと比べ、1位の Irad Ortiz Jr. は Saratoga と Belmont でも1位だった (p.16, Table 1)。2019 年の賞金順位は入手できなかった。
- **馬のタイプ**: 5戦以上の馬の速度プロファイルを Ward 法で階層クラスタリングすると、「序盤速く終いが鈍る」「平均的」「序盤遅く終いが強い」の3群に分かれた (pp.17-18, Fig.8)。
- **枠（スタートレーン）の反実仮想**: 無作為に選んだ6組の馬・騎手で 6! = 720 通りの枠の割り当てを各 100 回シミュレーション（計 72,000 レース）。2番枠が平均着順 3.28・勝率 0.21 で最良、6番枠が平均着順 3.88 で最悪。4〜6番枠では外ほど1〜3着の確率が単調に下がる (pp.18-19, Fig.9)。これは選んだ6組に固有の条件付き効果（CATE）で、全体の平均効果（ATE）には多くの組で平均する必要がある、と著者は述べる (p.19)。

## 批判的に読む

- **予測性能の定量評価がない。** 評価の方針（フレーム単位の予測、レース単位の結果、推定値の妥当性）は述べるが (p.13)、レース単位の着順確率の対数尤度・Brier スコア・的中率や、オッズとの比較は報告されていない。動的着順確率は1レースの図示のみ。
- 騎手評価の比較対象は3年後（2022年）の賞金ランキングで、時期も指標も違う。
- 学習とシミュレーションに同じ 2019 年のデータを使っており、動的着順確率の例が学習に含まれるレースかどうか明記がない。含まれていれば当てはまりの良さを示すだけ。
- 枠の実験は6組 1 セットだけで、結論の一般性は低い。枠の効果は、横移動モデルの空間共変量と内を回る距離の短さから生まれているはずで、モデルの仮定をそのまま反映している面がある。
- ドラフティングの抗力は単純化した形状の流体計算で、実測との照合はない。前面積 1 m² も仮定。共変量の係数の推定値は本文で確認できなかった（未確認）。
- コードは公開されているかどうか確認できなかった（未確認）。

## keiba-ai での使い方

- **今すぐは使えない**: JRA のフレーム単位の位置データは一般に入手できないので、モデルそのものは再現できない。
- **使える考え方**:
  - 能力を「レース中の位置の関数」として持つ（序盤の加速・中盤・終い）。JRA で入手できるコーナー通過順位と上がり3ハロンから、馬ごとの「前半型/後半型」の潜在プロファイルを作る特徴量設計の参考になる。仮説: コーナー通過順位の推移を低次元に圧縮した脚質プロファイル（本論文の3群に相当）は、単なる「前走の4角位置」より勝率予測の log loss を改善する。
  - 枠の効果は能力と交絡するので、単純な枠別勝率ではなく、出走馬を固定した条件付き効果として推定する、という発想。
  - 展開（ペース、他馬の後ろにつけるか）は、レース単位のモデルでは能力と区別できない。予測モデルにペース予測（逃げ馬の数など）を入れる動機になる。
- **評価の反面教師**: 生成モデルを作るときも、最終的にはレース単位の着順確率をオッズと比べた対数尤度で評価する。
