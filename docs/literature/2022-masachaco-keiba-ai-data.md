# 有料データ（JRA-VAN DataLab・地方競馬DATA・JRDB）の比較と、PC-KEIBA で取り込んだテーブルの落とし穴

> 一言で: スクレイピングをやめて有料データを使う前提で、JRA-VAN DataLab・地方競馬DATA・JRDB を比べ、PC-KEIBA で PostgreSQL に取り込んだ DataLab のテーブル（jvd_ra / jvd_se / jvd_um / jvd_hc）を「予想に使うとき何が危ないか」の目線で解説した記事。モデルの性能の話はほとんどないが、**レース前とレース後で中身が変わる列**の具体的な一覧が貴重。

著者は競馬AI系 VTuber「ユーミィちゃん」の技術支援をしている個人開発者。同著者の関連記事2本を添付した。

- 本体（2022年12月）: データ源の比較とテーブル構造。
- 添付 `masachaco-ese-fullstack`（2022年、「競馬予想AIを作っていたら、いつのまにか『エセ』フルスタックエンジニアになっていた話」）: LightGBM で AI を作り始めてからの1年の試行錯誤。
- 添付 `masachaco-daily-posting`（2023年12月、「毎日競馬予想を投稿する技術」）: 地方競馬を含め毎日予想を出すための運用構成と、netkeiba AI競馬予想マスターズ 2023 の成績。

## データ源の比較（本体「結論から先に言うと」の節）

| 提供元 | 対象 | 形式 | 月額（記事時点） | 著者の評価 |
|---|---|---|---|---|
| JRA-VAN DataLab | 中央 | .NET 向け SDK。PC-KEIBA で PostgreSQL に取り込める | 2,090円 | 基本データは揃うが、調教・パドックは弱い |
| 地方競馬DATA | 地方（ばんえい含む） | 個人用 SDK なし。PC-KEIBA で取り込める。DataLab とほぼ同じ形式 | 1,800円 | DataLab にあるのに無いデータがある |
| JRDB | 中央のみ | 独自形式のテキスト。パーサを自作 | 2,000〜3,500円程度 | パドック・調教コース・追い方・出遅れなど主観的な情報がある |

結論は「中央だけなら JRDB でほぼ足りる。中央と地方の両方なら DataLab の形式に揃えると地方にも対応しやすい」。
スクレイピングをやめた理由は、データ量が増えると収集に時間がかかる、サイトのリニューアルで書き直しが要る、後処理に時間を取られる、の3つ。

PC-KEIBA は過去データの取り込みは無料だが、リアルタイムオッズと直前の馬体重・馬場状態の取得には有料会員（月980円）が必要、とも書いている。

## テーブル構造とリークの落とし穴

本体の「PC-KEIBA経由で、PostgresSQLに取り込んだ、DataLabのよく使うデータ」以降の節。keiba-ai にとって一番役に立つ部分なので詳しく書く。

- **固定長・ゼロ埋め**: DataLab は固定長データなので、開催月日は `0101` の4桁、馬名は36バイトを空白で埋めている。`bamei = 'ディープインパクト'` では引けず、`like 'ディープインパクト%'` が要る。
- **レース詳細 jvd_ra**: キーは開催年・開催月日・競馬場コード・レース番号。距離・トラック・賞金・発走時刻が取れる。
  - 馬場状態と天候は、**結果が出たレースにしか入らない**。レース前の値はリアルタイムの天候テーブル jvd_we から取る必要がある。
  - 「出走頭数」は取消・除外を反映した**実際に出走した頭数**で、レース前は空。予定頭数（何頭立てか）は「登録頭数」から取る。
- **馬毎レース情報 jvd_se**: キーは上記＋馬番。騎手・調教師・負担重量と、レース結果（着順）も入る。
  - 馬体重・増減・人気など直前に変わる値はレース前には入らず、レース後に入る。直前情報は速報テーブル apd_sokuho_se から取る。
- **競走馬マスタ jvd_um**: キーは血統登録番号。芝での1着回数などの通算成績はレースのたびに更新されるので、過去レースの特徴量に使うと未来の情報が漏れる、と著者自身が注意している。
- **坂路調教 jvd_hc**: 追い方やコースが無く使いにくい。どのレースに対応する調教かも調教年月日から推測するしかない。
- 競馬場コードやトラックコードのマスタは DB に無く、仕様書の末尾から自分で起こす。条件戦の条件（「2歳未勝利」など）はレース名からは引けず、競走条件コードから取る。
- 地方競馬DATA は `jvd_` を `nvd_` に置き換えた同じ構造。ただし開催スケジュール表（jvd_ys 相当）が無い、レースごとの脚質が無い、中央所属馬と地方所属馬のデータがそれぞれ片方にしか無いことがあり、交流戦で困る。

## モデルづくりの経緯（添付 `masachaco-ese-fullstack`）

- AIうまたんの技術記事をなぞって LightGBM で作り始めた。ただし DataLab を使ったので、netkeiba のタイム指数は使えなかった。
- 当初は「人が作った指数は主観が入るので渡さない。実績値だけを渡す」という方針だった。
- 距離・競馬場ごとに特化したモデルを作ったが、学習の手間と予想範囲の狭さから、できるだけ1つのモデルで済む設計に移った。
- 実装上の教訓: ラベルエンコードした列を category 型にする、エンコーダをモデルと一緒に保存する（与える順番で番号が変わるため）、One-Hot で学習期間に存在しない騎手（2022年デビューの騎手など）が推論時に現れる問題。
- 特徴量の追加候補として出遅れ率・調教評価・休み明け判定・スピード指数を挙げている。
- 評価バッチ、neptune.ai による実験管理、SHAP、FLAML、ランキング学習、自動買い目出力を順に入れた。それぞれの数値は書かれていない。

## 運用と成績（添付 `masachaco-daily-posting`）

- 前日にデータを取り込み、夜間に集計してデータセットを出力する。当日はレース約15分前にリアルタイムデータ（馬場状態・馬体重）をマージして予測し、ツイートする。
- データ取得に Windows が要るので ConoHa VPS（月1,200円）を借り、PostgreSQL は Supabase の無料枠、予想バッチは CircleCI（月6,000分・メモリ2GB の無料枠）、常駐のキッカーは GCP 無料枠、公開は GitHub Pages。
- netkeiba AI競馬予想マスターズ 2023 では、予選1（10月）で38レースを買って回収率72.5%（24位）、予選2（11月）で50レースを買って回収率95.6%（8位）だった（「AI競馬予想マスターズに参加しています。」の節）。予想から買い目まで AI に決めさせたとしている。

## 批判的に読む

- モデルの精度・回収率の検証はほぼ書かれていない。大会の数字は 38〜50 レースと少なく、偶然の幅が大きい。
- 「主観を排除して実績値だけ」という方針は、JRDB の主観的データを有用と評価する本体の記述と緊張関係にあり、著者自身も一長一短としている。
- テーブルの記述は 2022年の PC-KEIBA と DataLab の仕様に基づく。列の意味は仕様書で確認したほうがよい。

## keiba-ai での使い方

- JRA-VAN を使うなら、**レース前に値が入る列と、レース後に入る列を分けたホワイトリスト**を作る。この記事の jvd_ra の馬場状態・天候・出走頭数、jvd_se の馬体重・増減・人気、jvd_um の通算成績はそのまま候補になる。過去データで学習するとレース後の値が入っているので、推論時に無い列を学習に使ってしまうリークになる。
- 頭数特徴量は「出走頭数」ではなく「登録頭数」（または取消を反映した直前の頭数）を使う。
- 地方競馬に広げるなら DataLab 形式に揃え、中央・地方の所属馬データの突き合わせを最初に設計する。
- 同じ「出走前データと出走後データで埋まる項目が違う」問題に [民谷 2021](./2021-tamiya-ranknet.md) も直前で気づいている。
