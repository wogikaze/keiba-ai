# JRDB の固定長ファイルを DB 化し、606 特徴を 129 に絞った lambdarank。条件別の過去成績で買い方を決めて実戦では負けた LT

> 一言で: JRDB の 11 種のファイルを PostgreSQL に入れ、2009 年以降の 42,491 レース（約 60 万行）で LightGBM の lambdarank（3着内を上位とするランキング）を学習した。606 項目を Null importance や Boruta で 129 に絞った。2024年5月26日の東京で、モデルの過去成績から「上位6頭の馬単 BOX が回収率 133.9%」の条件を選んで目黒記念などを買ったが負け、当日5レースを全部同じ買い方で買っても回収率 58%。競馬場・距離・クラス別のモデルや買い目の絞り込みで「回収率100%超」としているが、検証方法は示されていない。

VRChat の個人開発集会（2024年6月20日）の LT。原本は配布スライド PDF（30 枚）で、イベントの紹介ページ（YouTube 動画へのリンクあり）を attach した。ページ番号はスライド番号。

## データ

- データ取得元の比較（p.8）: JRA-VAN DataLab.（月額 2,090 円、SDK が Windows 限定、自動購入やオッズ解析には必須）、netkeiba（0〜1,027 円、スクレイピングのコードが公開されていて始めやすい）、JRDB（1,980〜2,480 円、独自データが多く URL で DL できるので環境を選ばない）。JRDB を選んだ。
- JRDB の BAC、CYB、HJC、KAB、KKA、KYI、SED、SKB、SRB、TYB、UKC の 11 種を使用（p.11）。固定長テキストで、当時はパース処理を公開している人がおらず苦労した。週単位と年単位の zip がある。
- 2009年以降を使用。雪・台風による開催中止、競走中止、発走除外を除外。ファイルが破損して変なデータが混ざることがある（p.13）。
- 学習データ: 42,491 レース、596,868 行（p.15）。

## 特徴量

- 作成したデータは 606 項目、Null importance と Boruta などで 129 項目に選択（p.15）。
- 東京・芝・2勝クラス以上・1800〜2400m のモデルでは、重要度の上位は騎手期待連対率・騎手期待3着内率・騎手期待単勝率（JRDB の騎手の期待値系の項目）（p.27）。
- 人が予想に使う情報や苦労して分析したデータを入れても、案外精度が上がらない（p.14）。

## モデルと目的変数

- LightGBM の lambdarank、3着以内に入る馬を上位とするランキング。評価指標は NDCG（p.15）。
- 運用: 前日までに開催データを取得して予測、当日朝に Slack へ対象レースを通知、発走15分前ごろに予想結果を通知（p.10、p.17〜19）。

## 評価と賭け方

- 当日朝、モデルの過去成績（競馬場・クラス・距離・頭数・券種ごと）から勝てそうな条件を確認する。例: 東京・OP・芝2400m で上位6頭を馬単 BOX で買うと、過去の的中率 73.9%、回収率 133.9%（p.18）。
- この「過去成績」の期間や、学習期間と重なっているかは書かれていない。

## 結果

- 2024年5月26日（東京）: 目黒記念などを買って負け（p.20）。
- 当日対象の5レースで、上位6頭に1〜3着が入ったのは3レース（青嵐賞、むらさき賞、白百合S）。馬単6頭 BOX で全レース買っていれば回収率 58%（払戻 8,830 円／購入 15,000 円）。本人は全部外した（p.21）。
- 「作ってみて思ったこと」（p.22）: モデルの予想をそのまま買っても回収率 100% を超えない。競馬場・距離・クラスで得意不得意があるので条件別にモデルを分け、モデルの傾向（実はランク4〜5番目の馬が当たりやすい）を見て買い目を絞ると 100% を超えた。数値と検証期間は示されていない。

## 落とし穴と教訓（著者の記述）

- 条件別にモデルを分けるとレース数が減り、学習データもテストデータも足りなくなる。ダミーデータで水増しする方法も分からない（p.23）。
- 6頭 BOX は当たるが点数が多く、購入金額で負ける（p.22）。
- JRDB はデータ自体はすぐ取れるので機械学習の題材としてはよいが、データに現れない要素も多い（p.25）。

## 批判的に読む

- 「回収率 100% 超」は、条件別の過去成績を見て買う条件を選んだ結果で、条件の選び方と評価が同じデータで行われている可能性が高い。条件（場×クラス×距離×券種×頭数）を細かく分けるほど、どれかが偶然 100% を超える。p.18 の 133.9% は、その条件で何レースの実績かが書かれていない。
- 実戦は1日・5レースで、結論は出せない。58% は控除率（馬単 25%）と点数の多さからみて想定内。
- 「ランク4〜5番目の馬が当たりやすい」は、lambdarank のスコアが確率として較正されていないことや、学習ラベル（3着内）と買い方（馬単）の不一致を示唆するが、検証されていない。
- 特徴選択（Null importance、Boruta）を時系列の検証期間の中で行ったかは書かれていない。全期間で選ぶとリークになる。

## keiba-ai での使い方

- JRDB を使う場合の実務情報（11 種のファイル名、固定長、週・年単位の zip、破損データ）として、データ取得の ADR の比較材料に使える。JRA-VAN・netkeiba・JRDB の比較表（p.8）も同じ。
- 「条件別に過去成績の良い買い方を選ぶ」運用は、選択と評価の期間を分けないと多重比較で過大評価になる。keiba-ai で条件別の買い方を試すなら、条件の選択は検証期間、評価はテスト期間に限定し、試した条件の数を記録する。
- 学習のラベル（3着内）と買う券種（馬単の着順）を揃える。馬単・3連単を買うなら、着順の確率（Plackett-Luce や [Harville 1973](./1973-harville-multi-entry-probabilities.md)）を経由して買い目の確率を出す。
