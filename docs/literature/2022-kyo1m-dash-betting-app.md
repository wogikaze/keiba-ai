# XGBoost の着順確率と、合成オッズで買い目の資金配分を計算する Dash アプリ

> 一言で: netkeiba からスクレイピングしたデータで XGBoost により着順を予測し、レースごとに確率を正規化した。2021年8月以降のテストで「1着確率0.5超の単勝を100円」買うと的中率51.6%・回収率109.9%。後半は、複数の買い目を合成オッズで束ね、どれが当たっても払戻が同じになる資金配分を計算する Dash アプリの紹介。

## データ

- netkeiba のレース結果ページ（`race.netkeiba.com/race/result.html?race_id=...`）を requests + BeautifulSoup（必要に応じて Selenium）で取得し CSV 化（「1. データ収集」の節）。
- 学習データは 2016年〜2021年7月（「3. 予測モデル作成」の節）。件数は書かれていない。
- 推論時は出馬表ページ（URL の `result` を `shutuba` にする）から取る。

## 特徴量

- 馬: 性別・馬齢・馬体重・体重変化・血統・前3走までの勝率などの成績・厩舎・トレセン。
- レース: 開催・クラス・芝ダ・距離・出走頭数・馬番・**オッズ**・騎手。
- カテゴリはラベルエンコード（「2. 前処理」の節）。
- 特徴量重要度の上位3つは、出走頭数・オッズ・芝/ダート（重要度の図）。

## モデルと目的変数

- XGBoost で着順を予測（モデル比較はしていない）。出力は各馬の順位ごとの確率で、レースごとに各順位の確率の和が1になるよう正規化している（「4. 予測作成」の節。著者は「少し小手先感がある」と書いている）。

## 評価と結果

「4. 予測作成」の節: 学習 〜2021年7月、テスト 2021年8月〜（終わりの日付は書かれていない）。1着確率が0.5を超えた馬の単勝を100円ずつ買うシミュレーションで、**的中率51.6%、回収率109.9%**。途中の回収率はぶれる、と購入額・払戻額の累積グラフで示している。

続く「5. 賭け方検討」で著者自身が「もちろん勝っていません」と書いている。理由として挙げているのは資金の制約で、シミュレーションどおりに買うには潤沢な資金が要る、という点。

## 合成オッズと資金配分（「合成オッズ」の節）

- 合成オッズ = 1 / Σ(1/オッズ)。
- 払戻を均等にする配分: 各買い目の購入額 = 総額 × 合成オッズ ÷ 各オッズ。
- 例: 馬連 2.0・5.0・8.0 倍を合計10,000円で買うと合成オッズ約1.21、各 6,100円・2,400円・1,500円で、どれが当たっても約12,000円。
- 合成オッズが1未満の組み合わせは、当たっても損をする。
- Dash アプリは、レース情報・馬券ごとの予測確率・オッズを表示し、選んだ買い目の合成オッズと均等払戻の配分を自動計算する。

著者のまとめでは、合成オッズを見て買うと「当たるが損もしない」買い方になりがちで、まだ儲かっていない。今後は予測確率・オッズ・期待値から払戻が最適になる組み合わせを自動で選びたい、としている。

## 批判的に読む

- **オッズの時点**: 学習・テストに使ったのは結果ページのオッズ、つまり確定オッズと考えられる。特徴量重要度の2位がオッズなので、テストの回収率109.9%は確定オッズで買えた前提の数字。実際に買う時点のオッズとは違う。
- 1着確率0.5超の馬はほぼ人気馬なので、買う数は少なく、回収率のばらつきは大きいはず。購入件数は書かれていない。
- 出走頭数が重要度1位なのは、着順の多クラス予測で「頭数が少ないほど上位になりやすい」という機械的な効果を拾っているため。勝ちやすさとは別。
- 合成オッズによる均等払戻は、期待値を上げる方法ではない。各買い目の期待値（確率×オッズ）が1を超えていなければ、配分を変えても期待値は1未満のまま。著者も最後にこの方向（期待値での選択）を課題に挙げている。

## keiba-ai での使い方

- 合成オッズ・均等払戻の配分は、買い目のリスク表示（どれが当たってもいくら戻るか）として UI や評価レポートに使える。最適化そのものは Kelly 系の配分で考える。
- 「確率の正規化」は、レース内で確率の和を1にする後処理の最小例。キャリブレーションの比較対象になる。
