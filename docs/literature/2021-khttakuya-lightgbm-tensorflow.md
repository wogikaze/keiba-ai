# 1日25レースで単勝回収率101%、ただし当日の確定オッズと全期間集計の連対率が入力に入っている

> 一言で: 平地レースのデータで「2着以内か」を LightGBM（Optuna で調整）と TensorFlow の2モデルで予測し、平均を取って上位4頭の単勝・複勝を買った。2021年11月7日の1日・25レースで単勝回収率101%、複勝89%。評価が1日だけで、入力に当日オッズ由来の特徴量と、テスト日を含む全期間で集計した連対率が入っている。

## データ

- CSV（`horsedata.csv`）を読み込んで使う。平地のみ。障害は数が少ないので除外（「使用するデータ」の節）。
- 入手元・期間・件数は本文に無い。列の説明は別記事（「競馬予測で使用する際のCSVデータ」）とスクリーンショットに回している。

## 特徴量（「前処理」の節）

- **前走成績**: 馬ごとに日付で並べて `shift(1)` し、前走の人気・オッズ・3角/4角順位・上り3F・着順を作る。
- **騎手の競馬場別連対率**、**父の競馬場・距離・芝ダ・馬場状態別の連対率と最頻脚質**、父のタイプ別の同様の集計: `pivot_table(..., aggfunc='mean')` を**全データ**に対して計算してマージ。
- 各コース・各距離で連対したときの3角/4角平均順位・上り3F・人気・オッズ。
- 生成特徴量: `odds / pop`（オッズ÷人気）とその2乗、前走との人気差 `pre_pop - pop`、前走とのオッズ差、父の上り3Fと前走上り3Fの差など。
- 着順・3角/4角順位・上り3F・走破タイムは「予想する際使えない」として削除している。

## モデルと目的変数（「モデル作成」の節）

- 目的変数: 1着または2着なら1（連対フラグ）。
- LightGBM: `optuna.integration.lightgbm` で自動調整。カテゴリ列（競馬場・クラス・芝ダ・距離・天候・馬場・性・父・母・騎手・調教師など）を LabelEncoder で数値化。
- TensorFlow: Keras の feature_column による構造化データ分類のチュートリアルを流用。数値列を標準化、馬番をバケット化。
- 2021/11/7 以降を予測対象、それより前を学習に使う。学習データの中は `train_test_split(shuffle=True)` のランダム分割で検証。
- 2モデルの予測を 0.5:0.5 で平均し、0.5 以上を1にする。片方が0.5以上なら〇、両方なら◎。

## 評価と結果

検証スコア（「スコア結果」の節）: LightGBM の binary_logloss 0.313、TensorFlow の val_loss 0.333・val_accuracy 0.861。

実戦（「レース結果」の節）: 2021年11月7日の福島・東京・阪神。新馬・障害・確率が極端に低いレースを除いた25レース。各レースで確率上位4頭に単勝100円×4、複勝100円×4。

| | 単勝 | 複勝 |
|---|---|---|
| 投資 | 10,000円 | 10,000円 |
| 払戻 | 10,110円 | 8,890円 |
| 回収率 | 101% | 89% |

単勝的中は25レース中22（4頭買いで約88%）、複勝は25レース全て的中。最高配当は単勝1,640円、複勝500円。
複勝が負けたのは「的中したのに損をした」（いわゆるガミ）が多かったため、と著者は分析している。

## 批判的に読む

- **当日オッズ・人気のリーク**: `odds` と `pop` 自体は入力から外しているが、`odds_hi = odds / pop` や `pre_pop - pop`・`pre_odds - odds` など、当日のオッズ・人気から作った列は残っている。学習データではこれらは確定値なので、確定オッズを入力しているのと同じになる。上位4頭の単勝的中率が88%と高いのもこれと整合的。
- **集計特徴量のリーク**: 騎手・父の連対率は全期間（予測日を含む）で `pivot_table` を取っているので、各レースの結果がそのレースの特徴量に入っている。時点を区切った集計ではない。
- **評価の短さ**: 1日25レース。単勝101%は投資10,000円に対し+110円で、誤差の範囲。
- 検証はランダム分割で、同じレースの馬が学習と検証の両方に入る。
- 上位4頭に均等に賭ける戦略では、単勝の的中率が高くても回収率は人気馬の配当に縛られる。

## keiba-ai での使い方

- 「オッズ列を削ったが、オッズから作った派生列が残っていた」という典型例として、特徴量ホワイトリストの検査（派生元の列まで辿る）のテストケースにする。
- 騎手・種牡馬の条件別連対率は有用な特徴量だが、必ずレース日より前のデータだけで集計する（expanding window か、前日までの累積）。
- 回収率の評価は1日では無理。最低でも数か月の時系列テストにする。
