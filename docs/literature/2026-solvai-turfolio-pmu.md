# フランス PMU の複勝プールで、外部検証1,069件 ROI +4.8%: 30分前オッズ・事前登録・複勝払戻モデル

> 一言で: フランス PMU の12年分（15.7万レース、196万頭）で、LightGBM＋Plackett–Luce レーティング＋直近20走を読むニューラルネットを条件付きロジットで結合し、発走30分前の基準オッズと重ねたモデルを作った。オッズを見ないモデル単体でも30分前の市場の log loss を −0.043 下回る。複勝（simple placé）を「3着内確率60%以上、期待払戻×確率が賭け金の1.1倍以上」で買う規則は、保留期間（749件）で +4.3%、規則を固定した後に取得した新しい期間（320件）で +6.1%、合計1,069件で +4.8%（95%CI +0.8〜+9.0%）。単勝・組み合わせ券はどれも残らず、香港では優位が出なかった。

## データ

- フランス: Hugging Face の `annaelmoussa/horse-racing-france`（PMU から取得、2014-01〜2026-05）。それ以降は PMU の公開 JSON API から同じ形式で取得（重なる2週間で項目ごとに一致を確認）。15.7万レース、196万の出走登録。速歩（繋駕・騎乗）、平地、障害を含む（research_log の「Data」）。
- オッズが2種類ある: **確定オッズ**（予定発走時刻の中央値1.8分後のスナップショット）と**基準オッズ**（発走約31分前に PMU が固定する値）。
- 香港: `eprochasson/horserace_data`（1979〜2018年6月、2.4万レース）。発走前オッズは2016〜18年の1,519レースのみ。
- 研究専用に Canalturf と SlyZouuu/turf-data（分単位オッズ）も使う。

## データの検査（モデル以前）

research_log の「Checks」より:
- 確定オッズ欄が実際に払われた価格であること（勝ち馬の公式払戻との比の中央値 1.000、94%が5%以内）。基準オッズは5%以内が11%しかなく、別の時点の価格。
- 通算成績が「そのレース時点」の値であること（連続する出走の間で出走数がちょうど1増える例が84%、増えない例は0.6%）。
- 単勝プールの 1/odds 合計の中央値 1.197（控除約16.5%）。本命・大穴バイアスは強い（暗黙40%超の馬は47%の暗黙に対し51.5%勝つ、2%未満は1.18%に対し0.84%）。
- 市場の log loss は確定オッズで 1.99、30分前の基準オッズで 2.04（速歩）。一様予測は 2.57。
- **レース後の項目を特徴量禁止リストとして列挙**（着順、タイム、km あたりタイム、着差、レース後コメント、事故など）。

## 特徴量とモデル

- 187個の発走前特徴量の勾配ブースティング、馬・ドライバー（騎手）・調教師の Plackett–Luce レーティング（相手の強さを調整）。
- ニューラルネット2種: 各馬の直近20走と成績文字列（form string）への attention、出走馬全体への transformer。各4シード。
- それらを条件付きロジットで結合した「基本確率」（当該レースのオッズを見ない）を先に作り、その上に30分前オッズを条件付きロジット＋残差 LightGBM で重ねる（スタッキング）。
- 複勝確率は着順モデル（2・3着の段階モデル）から、**期待払戻は複勝プールのモデル**（単勝オッズから各馬の複勝配当を推定。2019〜2024年で学習）から。

## 評価

- ウォークフォワード: Y 年は Y 年より前の年だけで学習。
- 事前登録: 規則は2024年までのデータで選ぶ。2025-01〜2026-05-05 の保留期間は規則ごとに1回だけ見る。その後、規則を固定して `results/*_preregistration.json` に書いてから、新しい6か月（2026-05-06〜11-05）を取得して1回だけ走らせる。
- 払戻は PMU の公式複勝配当、€10 均等。自分の賭け金による配当の低下も補正（+4.8% → +4.6%）。
- 確率の評価は勝ち馬の log loss（レース日単位のブートストラップ CI）。

## 結果

README「The record」と「Winner-prediction accuracy」、research_log より:

| 期間 | 件数 | 的中 | ROI | 95%CI |
|---|---:|---:|---:|---|
| 2019〜2024（規則を選んだ期間） | 2,711 | 67% | +5.4% | 標本内 |
| 保留 2025-01〜2026-05-05 | 749 | 69% | +4.3% | −0.7〜+9.3% |
| 新期間 2026-05-06〜11-05 | 320 | 69% | +6.1% | −1.3〜+13.8% |
| 外部検証合計 | 1,069 | 69% | +4.8% | +0.8〜+9.0% |

| log loss（保留、13,760レース） | 値 |
|---|---|
| 30分前の市場 | 2.023（1番人気勝率 30.4%） |
| オッズなしモデル | 1.980（−0.043） |
| モデル＋30分前オッズ | 1.952（−0.071） |
| 確定オッズの市場 | 1.932（33.0%） |
| モデル＋確定オッズ | 1.915（確定市場比 −0.017） |

- 改善の出どころ: 直近走を系列として符号化すること（相手の強さ込み）だけで約 −0.05。履歴がないネットは GBM と変わらず、出走馬間の attention は何も足さない。過去走が多い馬ほど改善が大きい（初出走 +0.02、20走以上 −0.07）。ネットに30分前オッズを直接入れる（end-to-end）より、市場と後段で重ねる方が良い（1.957 対 1.943、2022年）。
- 単勝: 30分前オッズでの単純な EV 規則は +2.4%（8,812件）だが新期間では単勝の規則はすべて負け（最も自信のある馬で −13%）。
- **30分前の価格を固定できるなら**（固定オッズや取引所）同じ判断で +27%〜+65%（すべて有意）。モデルは締切直前の資金の行き先を読めているが、パリミュチュエルではその資金が優位を消す。
- 組み合わせ券（couplé、trio）: Harville より大きく良いが、払戻率がそれぞれ74.8%・77.9% のプールに勝てず、ROI は −15.4%、−31.1%。
- 香港: ネットは基本モデルを改善（−0.04）するが、確定オッズへの上乗せは −0.004 で有意でない。

## 落とし穴と教訓

- **結果を使った絞り込みの罠**: 複勝の「純プール」（プール総額 − 3着内馬への票）で絞ると開発・保留とも +15% になったが、この量は本命が3着内に来ると小さくなるので、結果を使っていた。結果に依存しない量に替えると効果は消えた。
- 締切直前の資金の影響は年々強まっている（30分前→確定で勝ち馬のオッズが縮む幅は2023年7%、2026年半ば12%）。PMU の控除率の変更（2025-09-29の週に約1ポイント）、配当ラベルの変更もある。
- 新期間単独（320件）の CI は0を含む。+5% と0を確実に分けるにはさらに3,000〜4,000件必要と著者が書いている。期待利益は1日約€1。

## 批判的に読む

- 紙上の成績で、実際に賭けていない。基準オッズは PMU が30分前に固定するので購入時点で知り得る情報だが、払戻は確定配当なので、30分前の判断と実際の払戻の関係は正しく扱われている。
- 規則は1つではなく「多くの戦略を同じ手順で試して落とした」中から複勝規則が残っている。保留期間を規則ごとに1回ずつ見ているので、保留期間の結果にも選択の影響がある。新期間（320件）が唯一の完全な前向き検証で、その CI は0を含む。
- 複勝払戻モデルの精度が ROI を左右するが、その誤差は README に出ていない。
- LLM で作ったと検索結果の説明にある（リポジトリの説明文 "Can an LLM-built model beat the French PMU horse-racing pools?"）。数値は `turfolio verify` で配布済み予測から再計算できる。

## keiba-ai での使い方

- **「オッズなしの基本確率 → 市場と後段で重ねる」構成と、「確定オッズ」「購入時点のオッズ」「両方を使った上限」を並べる log loss 表**をそのまま主表の形にする。JRA でも締切数分前の時系列オッズで同じ表を作る。
- 直近20走を系列として読むモデル（相手の強さ付き）が、GBM の集計特徴量より −0.05 効いたという結果は、JRA でも試す価値が高い。過去走数別の改善幅を必ず出す。
- 複勝は、確率モデルとは別に**払戻（票の分布）のモデル**が要る。JRA の複勝・ワイドは払戻が人気の分布で決まるので、単勝オッズから複勝配当を推定するモデルを作り、その誤差を報告する。
- 「規則を固定して書き出してからデータを取得し、1回だけ走らせる」新期間検証は、実験ディレクトリのルール（結果を書き換えない）とよく合う。
- 純プールの罠は、プール・票数系の特徴量の時点チェックの事例として記録しておく。
