# netkeiba → LightGBM の競馬 AI を、モジュール・Factory・Policy に分けて継続運用できる形に書き直した記録

> 一言で: YouTube で競馬 AI 開発を連載していた著者が、netkeiba スクレイピングから LightGBM の3着以内二値分類、単勝の閾値買いシミュレーションまでを、Notebook のセルの山から `preparing / preprocessing / training / policies / simulation` のモジュールに作り直した設計の解説。モデルの新規性はなく、回収率も「閾値を厳しくすると 100% を超える領域があるが点数が少なくぶれが大きい」という程度。価値は、HTML を保存してから表を作る、レース日より前に絞った成績集計、レース内標準化スコア、回収率の標準偏差の算出など、再現可能なパイプラインの実務上の型にある。

## データ

- netkeiba.com をスクレイピング。カレンダーページ → 開催日のレース一覧 → `db.netkeiba.com/race/<race_id>` の順にたどる（「ステップ1-1」）。
- 5つの生テーブルを pickle で保存: レース結果、レース情報、払戻、馬の過去成績（horse ページ）、血統（ped ページ）。
- **HTML を保存してからテーブルに変換する**。後で列を追加したくなったとき、再スクレイピングを避けるため（「ステップ1-2」のポイント）。
- 予測時は出馬表ページ（`race.netkeiba.com/race/shutuba.html`）を馬体重発表後に取得する。前日に馬の過去成績と血統を更新しておく。

## 特徴量

- 馬の過去成績を集計してマージ（`DataMerger`）。集計対象（`TARGET_COLS`）は着順、賞金、着差、最初・最後のコーナー順位、コーナー順位と着順の差など。馬ごとに加えて、距離・芝ダート・開催場ごとの集計（`GROUP_COLS`）も作り、「これから走る条件の得意さ」を表す。
- **レース情報の日付より前の成績だけを集計する**。図で「2020年4月26日のレースを予測するとき、それ以降の成績を使ってはいけない」と説明し、リークの定義を示している（「ステップ2-2」）。
- 出走間隔、馬場・コース種別・性別・天気・開催・回り・クラスのダミー化。`horse_id`・`jockey_id` はラベルエンコードし、学習時と出馬表時で番号を揃えるマスタテーブルを `data/master/` に置く。
- 特徴量重要度の上位は騎手 ID、馬 ID、頭数、馬体重、獲得賞金、出走間隔、芝ダート別の過去成績。

## モデルと目的変数

- LightGBM の二値分類で「3着以内か」。`KeibaAIFactory.create(featured_data, test_size=0.3, valid_size=0.3)` で訓練・検証・テストに分け、ハイパーパラメータチューニング付きで学習。分割が時系列かどうかは本文に書かれていない。
- モデル・データセット・ハイパーパラメータを一つの `KeibaAI` オブジェクトとして `models/<日付>/<version>.pickle` に保存（Factory パターン）。

## スコアと賭け方

- `StdScorePolicy`: 予測確率をレース内で標準化し（平均を引いて標準偏差で割る、「レース内偏差値」）、相対評価にする。`BasicScorePolicy`（生の確率）、`MinMaxScorePolicy` も同じ抽象クラスで差し替えられる。
- `BetPolicyTansho`: 標準化スコアが閾値を超えた馬の単勝を買う。閾値を 0.5〜3.5 の 100 点で走査し、テストデータでの回収率を描く。

## 結果

- 「ステップ4B」の図: 閾値を厳しくして買う馬を絞ると単勝回収率が 100% を超える領域がある。例として閾値 2.0 では約 1,857 枚を買い、回収率は約 80%。100% を超える領域は「100レース予測して3枚だけ賭ける」ような点数で、統計的なぶれも大きいと著者自身が述べる。
- 回収率の標準偏差は、1レースの払戻 $X_i$ を独立同分布と仮定して $\sigma[r] = \sqrt{n}\,\sigma(X)/b$（$b$ は購入額）で計算し、図の帯として描く（「(補足)回収率の標準偏差の計算方法」）。

## 落とし穴と教訓（著者）

- Notebook でセルを複製して特徴量を追加すると、どのセルがどの特徴量を作るか分からなくなる。`data1.csv` のような名前のファイルが増える。
- カテゴリ変数の処理を列ごとのメソッドに分けると、変更の影響範囲が小さくなる。
- 2026 年9月の追記で、このシステムは設計を全面的に作り直した有料マガジンの新シリーズ（当日予測・自動投票・サーバー運用）に引き継いだとある。本文にリンクは残っていない。

## 批判的に読む

- **評価の分割が不明**: `test_size=0.3` のみで、時系列かランダムかが書かれていない。過去成績の集計はレース日で切っているので特徴量のリークは避けているが、分割がランダムなら同じ時期のレースが学習とテストに混ざる。
- **確定オッズと払戻の扱い**: 払戻テーブルの確定払戻で計算している。単勝オッズはスコア計算の入力からは除かれているが、締切前に買うときのオッズとは違う。
- **馬 ID・騎手 ID のラベルエンコード**: 決定木が ID の大小で分岐するため、意味のない順序に過学習しうる。重要度上位に ID が来るのはその兆候でもある。
- 閾値を 100 点走査してから「100% を超える領域がある」と読むのは多重比較になる。著者もぶれの大きさには触れているが、検証期間とテスト期間を分けた閾値選択はしていない。

## keiba-ai での使い方

- **HTML 保存 → パース → 生テーブル → 前処理の分離**は `data/raw/` 不変・`data/processed/` 再生成可能という本リポジトリの方針と一致する。パーサーを変えたら HTML から再生成できるようにする。
- **成績集計はレース日でフィルタしてから行う**処理を単体テストで固める（[gara_gara 2020](./2020-gara-gara-lightgbm-leak.md) の失敗の予防）。
- **レース内標準化スコア**は、二値分類の確率を相対化する最も簡単な方法。条件付きロジット（[Benter](./2019-benter-model.md)）やレース内ソフトマックスとの比較対象にする。
- **回収率の標準偏差の帯**を閾値曲線に付ける描き方は採用する。独立同分布の仮定を明記し、ブートストラップ（レース単位）とも比べる。
