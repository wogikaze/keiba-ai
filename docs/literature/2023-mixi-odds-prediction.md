# 単勝支持率を QuerySoftmax で予測して「予想オッズ」を作る、netkeiba の事業側の発表

> 一言で: netkeiba（MIXI グループ）の出馬表に載る「予想オッズ」を、ユーザー投票の集合知（俺プロオッズ）から AI 予測に置き換えるため、オッズではなく支持率（0.8/オッズ）を目的変数にし、CatBoost の QuerySoftmax でレース内の確率として直接学習した。前段に PairLogit の順位予測モデルを置き、上位人気の誤差を重く扱う重みを付ける。実オッズとの RMSE は、オッズ10倍以下の馬で俺プロオッズ 25.43 に対し 3.26 まで下がった。

2023年7月27日のイベント登壇資料（Speaker Deck 公開は 7月28日）。全 40 枚で、競馬は p.4〜35、残りはゲーム内レコメンドへの応用。原本は Speaker Deck のページ（トランスクリプト）で、スライド PDF を attach し、表の数値は PDF の画像から読んだ。ページ番号はスライド番号。

## 背景と問題設定

- netkeiba の出馬表の「予想オッズ」は、ユーザーが予想する「俺プロオッズ」の集合知で作られていた。投票数に精度が左右され、意図的な操作の可能性もある（p.6〜10）。
- オッズが予測できると、馬券予測 AI の期待値計算の精度が上がる（勝率×オッズで回収率を見積もるので、オッズの精度が回収率の精度に効く）、また一般ユーザーが人気を把握する指標になる（p.13〜14）。
- つまり、レース前（発売前）にオッズを予測する問題で、馬の勝敗予測ではない。

## データと特徴量

- 馬データ・騎手データ・場データを入力とし、前処理で統計量作成、カテゴリ値変換、血統ベクトル作成などを行う（p.21、p.30 の構成図）。
- 具体的な特徴量の一覧、期間、件数は示されていない。

## モデルと目的変数

目的変数はオッズではなく支持率（p.17〜19）。オッズ = 払戻率(0.8) / 支持率。支持率を使う理由:
- オッズは小さいほど上位人気で、1倍近くでは予測のずれで負の値になりうる。支持率は大きいほど上位人気で、比率計算もしやすい。

その1（p.21〜23）: LightGBM の回帰で各馬の支持率を予測し、後処理でレースごとに和を1に正規化してオッズに変換する。問題点:
- 各馬を単体で予測するので、同じレースの他馬との力関係が入らない。
- 正規化が後処理なので、損失が0でも正規化後の値がラベルと一致しない。
- 下位人気（100倍なら支持率 0.008）は予測が負に近づく。

その2（p.24〜31）:
- オッズ予測モデル: CatBoost の QuerySoftmax。グループ（レース）内で softmax を取り、出力がそのままレース内の確率になる。比率計算が損失に含まれ、負値も出ない。
- QuerySoftmax の損失は交差エントロピーが中心で、−log(x) は確率の小さい側で傾きが大きいため、下位人気の誤差の改善を優先してしまう。そこで前段に CatBoost の PairLogit による順位予測モデルを置き、予測順位に応じた重み（Rank Weight）を損失に掛けて、支持率の高い馬を優先させる（p.29、p.31）。
- 正解ラベルは実際の支持率（確定オッズから計算したものとみられる。明記はない）。

実オッズと予測オッズの RMSE を、オッズの上限（10倍・20倍・50倍以下の馬に限定）ごとに比較（p.32〜34）。AI オッズは ver.1〜4 の版があり、ver.2 が「その1」、ver.4 が「その2」。

## 落とし穴と教訓

- 目的変数をオッズにすると、スケールが非線形で負値や比率の問題が出る。確率（支持率）にして、レース内で和が1になる構造をモデルに入れるのがよい。
- 交差エントロピー系の損失は、確率の小さい馬（大穴）の誤差に引っ張られる。上位人気の精度が欲しいなら重み付けが要る。
- 重賞は投票数が多いので集合知（俺プロオッズ）も精度が高く、AI の優位は小さい。新馬戦や一般レースで差が大きい。

## 批判的に読む

- 学習・テストの期間と分割方法、データ件数が書かれていない。時系列で分けたかは不明。
- RMSE はオッズの絶対値（倍）で測っており、高オッズほど誤差が大きくなる。オッズ上限で区切ってはいるが、支持率や対数オッズでの誤差、確率としての LogLoss がないので、確率の質としての比較はできない。
- 予測対象が確定オッズなのか、発売中のある時点のオッズなのかが書かれていない。
- 勝敗予測ではないので、回収率の評価はない。オッズ予測が馬券 AI の回収率をどれだけ改善するかは主張だけで、検証はない。
- ver.1〜4 の違いのうち、ver.3 の中身は説明されていない。

## keiba-ai での使い方

- 「発売前（前日）に市場の支持率を予測する」モデルは、前日予測の運用で期待値を見積もるときに、確定オッズの代わりとして使える。keiba-ai で前日に買い目を決めるなら、予想オッズモデルを別に持つ設計を ADR の候補にする。
- 勝率モデル側でも、レース内 softmax（QuerySoftmax、条件付きロジット）で確率を直接学習する設計は、[Bolton 1986](./1986-bolton-conditional-logit.md) の条件付きロジットや [Benter 2019](./2019-benter-model.md) と同じ構造で、確率の和を後処理で揃える方法より筋がよい。CatBoost の QuerySoftmax を LightGBM の二値分類＋正規化と比べる実験ができる。
- 支持率の予測と勝率の予測の差（市場がどれだけ過小評価するか）を目的変数にする発想の材料になる。
- 損失の重み（人気上位を重くする）は、期待値ベットで問題になる低確率帯の誤差（[shoheimitani 2025](./2025-shoheimitani-ml-horse-racing.md)）とは逆向きの設計で、何を優先するかを目的に応じて決める必要がある。
