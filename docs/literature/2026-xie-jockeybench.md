# JockeyBench: JRA の過去データを時刻どおりに再生して LLM エージェントの予測と賭けを評価する

> 一言で: JRDB の12年分のデータを「公開された時刻」付きで再生する環境を作り、28 の LLM 構成に予測プログラムを書かせて 2024年1〜2月の 324 レースで評価した。最良のエージェントでも対数スコアは市場の締切オッズに大きく及ばず（0.525 vs 0.757 nats）、上限付き Kelly では全構成が平均で損をした。keiba-ai にとっては、オッズなしのファンダメンタルモデルと市場との差を JRA で測った基準表（Table 3）がいちばん役に立つ。

香港科技大学（HKUST-KnowComp）ほか。コードは GitHub で公開とされる (p.1)。

## 要旨

繰り返し起きるイベントの予測で、LLM エージェントの (1) 予測力、(2) 結果を見ての改訂（適応）、(3) 情報取得の費用、(4) 予測にもとづく意思決定の価値、を分けて評価するベンチマークと評価手順を提案する (p.1)。
エージェントにはオッズ・人気・配当・予想印・JRDB の指数を見せず、事実データだけから予測させる (p.1, p.3)。賭けは過去の公式配当で後から精算するだけで、実際の賭けはしていない (p.9)。

## データと時刻管理

- JRDB の会員向けアーカイブを生ファイルから解析し、2015〜2026年の 40,357 レース・564,224 出走をつないだデータベースを作った (p.3)。実験には 2024年の評価期間までのレースだけを使う。
- すべてのレコードに「公開された時刻」を付け、馬・騎手などの名前は仮名化。エージェントには5群（レース条件、馬の属性、調教、過去走、騎手・調教師の統計）97 フィールドだけを有料ツール経由で見せる (pp.3–4)。
- 時刻の再生: 翌日の出馬表は前日 21:00 JST に公開、着順は当日 20:30 JST に公開。予測は結果公開前に封印する (p.4)。
- 主評価: 2024年1月6日〜2月3日の10開催日・324 レース (p.5)。

## 評価の仕組み

二つのワークフローを比べる (pp.4–5, Figure 2)。

1. **Program**: LLM が予測プログラム（コード）を書き、環境がそれを各レースで実行して順位と単勝確率を出す。毎日結果を見て改訂できる。同じ初期プログラムを改訂せずに走らせる「凍結対照」と対にして、改訂の効果を測る。
2. **Adaptive Acquisition**: LLM が書いた「証拠収集プログラム」が情報を集め、レースごとに新しい LLM セッションが予測する。

予測の評価は平滑化した対数スコア (p.4):

$g_r = \ln\big(\tfrac{n_r}{k_r}\sum_{i\in W_r}\tilde p_{ri}\big)$, $\tilde p_{ri}=0.98\,p_{ri}+0.02/n_r$

$n_r$ は出走頭数、$W_r$ は勝ち馬の集合（同着で $k_r$ 頭）。一様予測なら 0、単位は nats。これに加えて Top-1（予測1位の勝率）と Top-3 精度。
ほかに、データ取得セル数・ツール呼び出し・CPU 秒に課金する合成効用 Net（score-yen）を定義するが、厳密な適正スコアではないと著者が断っている (p.5)。

賭けの精算は二通り (p.5): 予測1位に単勝100円の均等買い、および $f_r=\max\lbrace 0,(q_rO_r-1)/(O_r-1)\rbrace $ の Kelly 比率を日初資金の1%で頭打ちにした買い方。$O_r$ は発走前の最後のオッズ（JRDB の TYB スナップショット）で、エージェントには見せていない。配当は控除率 20% 込みの公式単勝配当 (p.2, Figure 1)。

オフライン参照は 2018年1月6日〜2023年12月28日の 20,730 レースで学習し、時間順に約 80/10/10 で学習・選択・温度較正に分けた (p.16)。
学習レース数を変えた比較では、18特徴の条件付きロジットは 1,000 レースでほぼ頭打ち（0.461）、幅広い特徴の GBDT は 10,000 レースまで伸び続ける（0.466 → 0.606）(p.21, Table 9)。

### エージェント（Table 2, p.6）

| 構成 | 対数ゲイン | Top-1 % | 改訂の効果 A−S |
|---|---|---|---|
| GPT-6.1-Sol | 0.525 | 28.5 | +0.000 |
| GPT-6-Astra | 0.523 | 30.0 | +0.000 |
| Claude Opus 5 | 0.484 | 28.2 | −0.001 |
| Kimi-K3 | 0.350 | 24.9 | +0.316（有意） |
| Qwen3.5-9B | −0.280 | 13.2 | −0.304（有意） |
| 締切オッズ（参考） | 0.757 | 34.0 | – |

- 28構成中、Holm 補正後に改訂で有意に改善 7、悪化 2。最上位の2構成は改訂の効果がゼロで、最終スコアの順位と適応力は別物 (p.6)。
- 最良エージェント 0.525 は「エージェント由来の特徴」参照 0.523 とほぼ同じで、「幅広い事実特徴」0.608 には届かない (p.6)。
- 上限付き Kelly では全 28 構成で平均損益が負。138 の個別実行のうち黒字は 13 (p.7)。別に保存した 22 モデル・54 実行の単勝均等買いの回収率は −19.7%（プール）(p.7, Table 14)。控除率 20% とほぼ同じで、予測1位の単勝を買うだけでは控除分を取り返せないことと整合する。
- **選んだ賭けの上で確率バイアスが逆転する。** DeepSeek の Adaptive では、全予測1位では予測確率 18.14% に対し実勝率 21.25%（過小予測）なのに、Kelly が選んだ賭けでは 17.83% に対し 7.82%（大幅な過大予測）(p.8)。
- **黒字の実行は少数の大当たりに依存しうる。** DeepSeek Adaptive R1 は Kelly で +1,470 円だが、総払戻の 55.35% が3枚の当たり券によるもので、他の5実行は平均 −47,568 円 (p.8)。MiMo の Program は5実行で −70,500 〜 +73,080 円とばらつく。

> Thus, average bias across all forecasts can conceal overprediction on the subset used for decisions. (p.8)

## 批判的に読む

- **評価期間が短い。** 主評価は 10 開催日・324 レース。日単位クラスタの CI を出しているが、賭けの損益は数百レースでは分散が大きすぎる。著者も、繰り返し実行は同じ結果上での構築のばらつきで、独立な時間的再現ではないと書いている (p.8)。
- **予測1位の単勝を買う均等買い**は、確率と市場オッズを比べていないので、予測の価値の検定としては弱い。Kelly 版は市場オッズを使うが、1% で頭打ちにしている。
- **オッズは TYB スナップショットで精算**しており、実際の締切オッズとの差（オッズの変動）は扱っていない (p.7)。
- エージェントの学習データは 87 レースの「サポート」と各自が取得した履歴で、オフライン参照（20,730 レース）とはデータ量が違う。著者は差をエージェントの能力だけには帰せないと断っている (p.6)。
- 「エージェント由来の特徴」は事後選択なので、その参照値は楽観的 (p.7)。
- 生データは商用会員のアーカイブで、公開は許諾の確認待ち (p.9)。再現には JRDB 会員が必要と思われる。
- モデル名（GPT-6.1-Sol、Claude Opus 5 など）は 2026年10月時点のもので、モデルの比較は時間が経つとすぐ古くなる。この論文の持続的な価値は、参照モデル表と評価手順の方にある。

## keiba-ai での使い方

- **市場との差の基準値。** JRA の 2024年前半で、オッズを使わない最良の参照（ロジット＋GBDT）が 0.573〜0.608 nats、発走前オッズ 0.675〜0.700、締切オッズ 0.719〜0.757（いずれも一様予測との差）。keiba-ai のオッズなしモデルの対数スコアを同じ尺度（一様予測からの nats）で出せば、この表と直接比べられる。仮説: 「keiba-ai のファンダメンタルモデルは 0.6 nats 前後で頭打ちになり、締切オッズとの差 0.15 nats を埋めるには Benter 型の市場確率との結合が必要」。
- **学習データ量の目安。** Table 9 から、線形の条件付きロジットは 1,000 レースで飽和し、特徴を増やした GBDT は 10,000 レース以上で効く。特徴を増やす実験では学習期間も十分長くする。
- **賭けの評価規律。** (1) 全予測での較正だけでなく、実際に賭けた部分集合での較正（予測確率と実勝率）を必ず出す。Kelly のように「市場より高く見ている馬」を選ぶ規則は、過大予測した馬を選びやすい（勝者の呪い）。(2) 黒字の検証は、払戻の上位数件を除いても黒字かを確認する。(3) 対照（凍結モデル、一様予測、市場）との対にした差で改善を判断する。
- **時刻管理の設計。** 全レコードに公開時刻を付け、予測時点より後のものを見えなくする方式は、keiba-ai のリーク対策の手本になる（前日 21:00 の出馬表、当日の結果）。
