# 0002 評価指標（下書き）

> [0004](./0004-evaluation-axes.md) で置き換えた。

## 状況

ベースラインを並べる前に、共通の評価ライブラリ（`src/keiba_ai/market.py`、`src/keiba_ai/evaluate.py`）を作った。
どの指標を主指標にするか、ブートストラップの単位をどうするかはまだ決めていない。
この ADR は、ライブラリで計算できるものを並べるだけの下書きである。

## ライブラリで計算できるもの

- オッズ → 勝率: 比例正規化、べき乗法、Shin 法、goto_conversion。取消・欠損オッズは除いて正規化する。
- レース単位の条件付き対数損失（−log p_勝ち馬 のレース平均）、多クラス Brier、top-1 的中率、較正表と ECE。
- 同着: 的中を等分した目標（t = y/Σy）で損失を計算する。払戻しは各勝ち馬の払戻オッズで計算する。
- ΔlogLoss（モデル − 参照）: レース単位または日付単位のクラスタブートストラップ CI と、正規近似の p 値。
- Benter の 2 段階: p ∝ exp(α·log p_model + β·log p_market) を学習期間で当てはめ、テスト期間で結合 vs 市場の ΔlogLoss を測る。
- プラセボ: レース内で確率を並べ替える。学習を含む偽モデル（時間をずらしたラベルなど）は callable で渡す。
- 単勝の均等賭け: 判断用オッズと払戻用オッズを別の列で渡す。ROI（控除率込み）とクラスタブートストラップ CI、最大ドローダウン。
- 時系列分割: 日付の境界で train / valid / test に分ける。

## 未決定

- 主指標（ΔlogLoss vs 市場か、Benter の α か）と、比べる市場確率（締切何分前のオッズか、どの変換法か）。
- ブートストラップの単位（レースか開催日か）。
- 分割の境界とウォークフォワードの刻み。

## 気づいたこと

- goto_conversion は控除が大きいと大穴の確率が負になり、比例正規化に戻る。控除 20% の合成データでは約 78% のレースで戻った。JRA 単勝ではほぼ比例正規化と同じになる見込み。
