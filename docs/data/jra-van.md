# JRA-VAN Data Lab.（JV-Link / JV-Data）

> 一言で: JRA 公式データを配信する有料サービス（月額 2,090 円、JV-Link インストールから 1 か月お試し）。Windows の COM 部品 JV-Link を通じて、1986 年以降のレース・出走馬・払戻・確定オッズと、各種マスタ・調教・血統を固定長テキストで取れる。発走前の**時系列オッズ**は単勝・複勝・枠連・馬連だけで、保証される提供期間は 1 年。ただし実際には 2003 年 10 月以降のレースまでさかのぼれた、という報告が複数ある。それ以外の券種の発走前オッズは、開催中に自分で記録するしかない。

取得の計画は [31日間の取得計画](./jra-van-download-plan.md) に書いた。

## サービスの仕組み

| 名前 | 何か |
|---|---|
| JRA-VAN Data Lab.（データラボ） | JRA の公式データの配信サービス。データを直接見るサービスではなく、対応ソフトを通じてデータを使う（[DG] 1.1, p.7） |
| JV-Link | JRA-VAN のサーバーとやり取りする Windows の ActiveX COM 部品（ProgID `JVDTLab.JVLink`）。ダウンロード・復号・キャッシュ・セットアップを受け持つ（[DG] 1.2, 3.1.1, p.8, 12）。動作環境は日本語版 Windows 11、64bit CPU（[DG] 2.1, p.11） |
| JV-Data | 配信されるデータの総称。Shift JIS（半角は JIS8）の固定長テキストで、1 行 1 レコード。先頭 2 バイトがレコード種別 ID（`RA`、`SE` など）（[JVD]「フォーマット」冒頭） |
| JRA-VAN Data Lab. SDK | 仕様書、JV-Link のインストーラ、サンプル（VC++・VB・Python 3.14）、JV-Data 構造体（Python 版 `JVData_Struct.py` を含む）、検証ツール（[DG] 1.3, p.10） |
| TARGET frontier JV | データラボ会員が無料で使える代表的な分析ソフト。時系列オッズの一括ダウンロードと CSV 出力の機能がある（[todaitired 2026](../literature/2026-todaitired-jra-lightgbm-odds.md) の添付 `target-odds`）。keiba-ai では使わず、JV-Link を Python から直接呼ぶ |

Python からは pywin32 で COM オブジェクトを作る（SDK の `sample1_Python3.14/Form1.py`、[DGPy] 1.1.3, p.9）。
SDK は 64bit 版なので Python も 64bit にする。

データの流れは「JVOpen / JVRTOpen で要求 → JV-Link がサーバーからファイルを落として保存パスに置く → JVRead / JVGets で 1 行ずつ読む → JVClose」（[JVL] 2.2, p.17–32）。

## JV-Link の使い方の要点

### 呼び出しの順番

1. `JVInit(sid)`: 最初に 1 回だけ呼ぶ。sid はソフトウェア ID（最大 64 バイト、英数字・スペース・`_` `.` `/`、先頭はスペース不可）。登録ソフトでなければ `"UNKNOWN"` を使える。サーバーとは通信しない（[JVL] JVInit, p.10）。
2. 設定（初回だけ）: `JVSetUIProperties()` はダイアログで保存フラグ・保存パス・利用キー・払戻ダイアログ表示を設定する（[JVL] p.11–13）。個別に設定するなら `JVSetServiceKey(key)`（p.14）、`JVSetSaveFlag(1)`（p.15）、`JVSetSavePath(path)`（p.16）。値はレジストリに保存され、次の JVInit / JVOpen / JVRTOpen で反映される。
   - 保存パスは**存在するフォルダ**を指定する。無いと JVOpen が -211 になる。データはその下の `cache` と `data` フォルダに置かれる（[JVL] JVSetSavePath, p.16）。既定はインストール先（`Program Files\JRA-VAN\Data Lab`）。
   - 保存フラグを「保存する」にすると、サーバーで提供されている間はファイルをローカルに残す（p.15）。2 回目以降の JVOpen はローカルにあるファイルをダウンロードしない（JVOpen の解説, p.20）。
3. `JVOpen(dataspec, fromtime, option, readcount, downloadcount, lastfiletimestamp)`: 蓄積系データの要求（p.17–21）。ダウンロードは別スレッドで始まり、すぐ戻る。
4. `JVStatus()`: ダウンロード済みファイル数を返す。これが downloadcount と一致したら完了。完了前に読むと予期しないエラーが出ることがある（p.24）。
5. `JVRead(buff, size, filename)` / `JVGets(buff, size, filename)`: 1 行（1 レコード）ずつ読む。戻り値は正ならバイト数、**-1 はファイルの切り替わり（エラーではない）**、0 は全ファイルの終わり、-3 はダウンロード中（p.25–28、コード表 p.56）。
   - JVGets は SJIS のままバイト配列で返すので速い（p.28）。ただし Python（pywin32）で JVGets を使うと 1 件ごとにバッファ分のメモリが残る漏れが報告されている（[crossclub_lab 2026](../literature/2026-crossclublab-jvlink-python.md) の失敗 8）。keiba-ai では JVRead を使う。
   - レコード末尾に CR/LF（と NUL）が付いている。保存前に落とす（同ノートの失敗 5）。
6. `JVSkip()`: 読んでいるファイルの残りを飛ばして次のファイルへ。蓄積系は 1 ファイルに 1 種類のレコードしか入っていないので、要らないレコード種別を飛ばすのに使う（p.29–30）。
7. `JVClose()`: 読み込みの終了。次の JVOpen / JVRTOpen の前に必ず呼ぶ（呼ばないと -202）（p.32、コード表 p.54）。`JVCancel()` はダウンロードの中止（p.31）。

### JVOpen の dataspec・fromtime・option

- **dataspec**: 4 文字のデータ種別 ID を連結した文字列（例 `"RACE"`、`"RACEDIFN"`）。複数まとめると JVRead が遅くなる既知の障害があるので、種別ごとに開くか、fromtime に終了時刻を付けて小分けにする（[JVL] p.17）。
- **fromtime**: `YYYYMMDDhhmmss`（その時刻より後に**提供された**データ）か、`YYYYMMDDhhmmss-YYYYMMDDhhmmss`（開始より後、終了まで）。TOKU・DIFF/DIFN・HOSE/HOSN・HOYU・COMM は終了時刻を付けられず、付けると -1（該当なし）になる（p.17–18）。
  - 通常データの fromtime は「前回の続き」を表す。前回の JVOpen が返した `lastfiletimestamp` を保存して、次回の fromtime に渡す（[DG] 3.3.4, p.22）。
  - セットアップの fromtime は「何年以降のレースを取るか」を表す（例: 1991 年以降なら `19910101000000`）。マスタ類は fromtime によらず全件が対象（[DG] p.22）。期間を区切って複数回に分けるときは、返ってきた lastfiletimestamp ではなく**自分で指定した終了日時**を次の開始にし、最後の 1 回は終了時刻なしで取る（[DG] p.23）。
- **option**（[JVL] p.18, 20、[JVD]「データ種別一覧」末尾の表）:

| option | 名前 | 何が返るか | 指定できる dataspec |
|---|---|---|---|
| 1 | 通常データ | サーバーにある全データのうち、fromtime より後に提供された差分。蓄積系ソフトがデータベースを最新に保つためのもの | TOKU, RACE, DIFF, BLOD, SNAP, SLOP, WOOD, YSCH, HOSE, HOYU, DIFN, BLDN, SNPN, HOSN（COMM・MING は [JVD] の表では可、[JVL] の表では不可） |
| 2 | 今週データ | 先週の結果と次週のレース関連（出走予定馬の過去走を含む）の約 1 週間分だけ。非蓄積系ソフト向け | TOKU, RACE, TCOV, RCOV, SNAP, TCVN, RCVN, SNPN |
| 3 | セットアップ | セットアップ専用データ（前月まで）のうち fromtime より後のものと、今月の通常データ。初回に過去データを全部入れるためのもの。スタートキットの有無を聞くダイアログが毎回出る | TOKU, RACE, DIFF, BLOD, SNAP, SLOP, WOOD, YSCH, HOSE, HOYU, COMM, MING, DIFN, BLDN, SNPN, HOSN |
| 4 | ダイアログ無しセットアップ | 3 と同じデータ。ダイアログは初回だけで、2 回目以降は初回に選んだ取得元を使う。種別ごとに分けてセットアップするときに使う | 3 と同じ |

- スタートキット（CD/DVD）の提供は 2022 年 3 月で終わったので、ダイアログでは「持っていない」（全部サーバーから取る）を選ぶ（[JVL] p.20–21）。
- セットアップでも TOKU（特別登録馬）は最新分（当週＋翌週）しか取れない。過去分は option 1 で fromtime を過去にして取る（[JVL] p.21 ※1）。
- 中断と再開: 通常データは最後に読んだファイルの `m_CurrentFileTimestamp` を fromtime にして開き直す。セットアップは同じ引数で開き直し、最後に読んだファイル名まで JVSkip する（[JVL] p.19）。
- JV-Link は読み込み順がレコードの作成時刻順であることを保証しない。キーとデータ作成年月日を比べて、新しければ更新・古ければ無視・無ければ挿入する（[DG] 3.3.5, p.25、[JVD]「フォーマット」冒頭）。

実践者の報告（[crossclub_lab 2026](../literature/2026-crossclublab-jvlink-python.md)）:

- option 4 でもダイアログが出て JVOpen が戻らないことがあり、別プロセスで画面のボタンを押して回避した。[jvdata-store](https://github.com/ht-0328/jvdata-store) の README は「一度対話的に通せば以降は自動で動く」としている。
- WOOD だけ option 4 で -301 になり、option 1 にすると通った。
- 1 回の JVOpen で開くファイル数が多いと極端に遅くなる（4,318 ファイルで毎秒 21 件、77 ファイルで毎秒 6,512 件）。1 年ずつ開くと解決した。ただし DIFN は期間指定すると全部 -1 になる。

### JVRTOpen（速報系）と JVWatchEvent

- `JVRTOpen(dataspec, key)`: 速報系データの要求。dataspec は 1 種別だけ。key は提供単位に合わせる（[JVL] p.22–23）:
  - レース単位: `YYYYMMDDJJKKHHRR`（年月日・場コード・回次・日次・レース番号）または `YYYYMMDDJJRR`
  - 開催日単位: `YYYYMMDD`
  - 変更情報単位: JVWatchEvent のイベントが返す文字列
- JVRTOpen はデータを受け取り終えてから戻る。1 回の JVRTOpen は 1 ファイルなので JVSkip は意味がない（p.23, 29）。
- `JVWatchEvent()` を呼ぶと、払戻確定・騎手変更・天候馬場状態変更・コース変更・出走取消/競走除外・発走時刻変更・馬体重発表のイベントが届く。イベントの引数を key にして、払戻確定は 0B12、馬体重は 0B11、それ以外は 0B16 を JVRTOpen する（[JVL] JVWatchEvent, p.49–51）。Python での受け方は [DGPy]。
- 同じ key で JVRTOpen を 2 回目以降呼ぶと最初の版が返り続ける、という不具合報告がある（0B30・0B31・0B33〜0B36・0B41。2026-10 の [jrvltsql issue #288](https://github.com/miyamamoto/jrvltsql/issues/288)）。JVLinkAgent.exe の再起動や 16 桁キーでも直らなかったとある。原因と回避策は未確認。開催中にオッズを繰り返し取る計画は、これを最初に確かめる。

## 時系列オッズ

研究の評価（回収率）は「買う時点で見えていたオッズ」で計算したい。確定オッズで計算すると、締切直前の資金流入の情報を使ってしまい楽観的になる（[todaitired 2026](../literature/2026-todaitired-jra-lightgbm-odds.md) の odds-timeseries、[rindokulab 2026](../literature/2026-rindokulab-odds-time-series.md)）。JRA-VAN でどこまで取れるかをまとめる。

### どのデータで提供されるか

| 取り方 | 券種 | 時点 | 過去の分 |
|---|---|---|---|
| 0B41（JVRTOpen） | 単勝・複勝・枠連（O1） | 発売開始から締切までの中間オッズを複数時点 | 保証は 1 年。実績では 2003-10-04 以降 |
| 0B42（JVRTOpen） | 馬連（O2） | 同上 | 同上 |
| 0B30〜0B36（JVRTOpen） | 全券種（O1〜O6） | 呼んだ時点の最新 1 版（中間・前日売最終・最終・確定のどれか） | 1 週間。過去の途中経過は残らない |
| RACE の O1〜O6（JVOpen、セットアップ可） | 全券種 | **確定オッズだけ** | O1・O2 は 1993 年 6 月、O6 は 2004 年 8 月から |
| SE の単勝オッズ・単勝人気順 | 単勝 | 確定（成績データ） | 1986 年から |

- O1・O2 の「発表月日時分」は中間オッズのときだけ入り、時系列オッズを使う場合だけキーになる（[JVD]「フォーマット」7.オッズ1 項番10、8.オッズ2 項番10、PDF p.14–15）。データ区分は 1 中間、2 前日売最終、3 最終、4 確定、5 確定（月曜）、9 レース中止（同 項番2）。
- O1 には単勝オッズ・人気、複勝の最低/最高オッズ・人気、枠連オッズ・人気と、各券種の票数合計（百円単位）が入る。馬連の O2 も同様に組番ごとのオッズ・人気と票数合計。
- **ワイド・馬単・3連複・3連単には時系列オッズが無い**。JRA-VAN の TARGET FAQ も「時系列オッズは単勝・複勝・枠連・馬連だけ」と書いている（[TARGET FAQ 667](https://targetfaq.jra-van.jp/faq/detail?site=SVKNEGBV&category=47&id=667)、[開発者コミュニティ topic 872](https://developer.jra-van.jp/t/topic/872)、2026-06-16）。この 4 券種の発走前オッズは、開催中に 0B33〜0B36（または 0B30）を自分で繰り返し取って時刻つきで保存するしかない。

### 何分刻みか

- 仕様書には刻みの記載が無い（[JVD] は「該当レースの複数時間帯のオッズ」とだけ書く）。
- JRA-VAN の TARGET FAQ は「5〜10 分間隔」としている（[TARGET FAQ 667](https://targetfaq.jra-van.jp/faq/detail?site=SVKNEGBV&category=47&id=667)）。
- jvdata-store の README は「5 分刻み（締切前は 1 分刻み）」と書いている（出典は書かれていない）。
- 1 レースの 0B41 が 110〜113 版あったという報告がある（[jrvltsql issue #288](https://github.com/miyamamoto/jrvltsql/issues/288)、2026-10-18）。前日発売からの 5〜10 分刻みとしては多いので、締切前に細かくなる可能性はある（推測）。
- **正確な刻みは未確認**。お試し期間の最初に、数レースの 0B41 を取って発表月日時分の間隔を数える。

### 過去何年分さかのぼれるか

- **保証は 1 年**（[JVD]「データ提供タイミング･提供単位」の 0B41・0B42 の提供期間）。過去のレースでもレースの key を指定して JVRTOpen で取れる。速報系なので、セットアップや JVOpen では取れない。
- **実績では 2003 年 10 月 4 日以降のレースまで取れた**。2024-03-04 時点（topic 72）と、2026-06-16 の回答（topic 872）で同じ日付が出ている。TARGET FAQ は 2008 年 2 月時点で同じ日付まで取れたと書き、今後制限される可能性があるので実際にダウンロードして確かめるしかない、としている。
- jvdata-store の作者は、実機で「約 1 年前から先週までのレース」で取れることを確かめている（[PR #8](https://github.com/ht-0328/jvdata-store/pull/8)）。1 年より前は試していない。
- 時刻を指定して一部だけ取ることはできない。発売開始から現時点までを全部取り、要らない時点は JVRead のときに捨てる（[JRA-VAN FAQ 231](https://support.jra-van.jp/jravan/detail?site=SVKNEGBV&category=16&id=231)）。

結論:

1. 単勝・複勝・枠連・馬連の時系列オッズは、**過去 1 年分は確実に、2003 年 10 月以降は取れる見込み**で、蓄積（セットアップ）ではなく速報系 0B41・0B42 をレースごとに取る。取れる年は時間とともに減るかもしれないので、お試し期間中に取れる限り取って手元に残す（解約時は削除が必要）。
2. ワイド・馬単・3連複・3連単の発走前オッズは、過去分はどこからも取れない。研究に要るなら、契約を続けて毎週末 0B33〜0B36 を記録する。
3. 確定オッズは全券種、RACE のセットアップで 1993〜2004 年から取れる。評価の基準線（確定オッズでの回収率）にはこちらを使う。

所要時間の目安: JVRTOpen 1 回で約 1 秒、1 年分（約 3,500 レース）で約 2 時間（jvdata-store README）。PR #8 は 1 年で「数時間」。仕様書に記載はない。

### キーと結合

- レースのキーは 開催年・開催月日・競馬場コード・開催回・開催日目・レース番号。SE はこれに馬番（区分 1 では馬番が初期値なので血統登録番号）を足す（[JVD]「フォーマット」の「キー」列、「特記事項」3.馬毎レース情報 項番11）。
- 時系列オッズ（O1・O2）はさらに発表月日時分がキーになる。
- 馬は血統登録番号（生年 4 桁＋品種 1 桁＋5 桁）、騎手・調教師はそれぞれのコードで結ぶ。
- 固定長で、文字列は全角スペース・半角スペースで埋まっている。数値の初期値は `0`（[JVD]「フォーマット」冒頭）。コード（競馬場・トラック・馬場状態など）の意味は「コード表」シートから自分でテーブルを起こす。
