# 加工済みテーブル（JRA-VAN）

JRA-VAN の生データ（JV-Data）から作る parquet のテーブルの説明。
モデル・評価はこのテーブルだけを読み、生データは直接読まない。

テーブルは `data/processed/jra-van/` に置く（git 管理外）。
JRA-VAN のデータそのもの・加工したテーブルは公開しない（[JRA-VAN のページ](./jra-van.md)の「利用規約上の制約」）。
このページに載せるのは、仕様の要約と集計した件数だけ。

## 作り方

```sh
uv run --extra ml python scripts/build_dataset.py                 # 全テーブル（差分更新）
uv run --extra ml python scripts/build_dataset.py --force         # 全部読み直す
uv run --extra ml python scripts/build_dataset.py --tables races entries --years 2024   # 一部だけ
uv run --extra ml python scripts/build_dataset.py --validate      # 下の「検証」の集計を出す
```

- 入力は `/mnt/e/keiba-ai/jra-van/raw/`（環境変数 `KEIBA_JRAVAN_RAW` か `--raw` で変えられる）。読むだけで、書き込まない。
- コードは `src/keiba_ai/jvdata/`（`layout.py` 仕様書の読み込み、`parse.py` 固定長の切り出し、`tables.py` レコードごとの変換、`build.py` 組み立て、`validate.py` 検証）。
- レコードのレイアウト（項目の位置・長さ・繰返し）は、仕様書の「フォーマット」シート（`data/raw/jra-van/specs/text/JV-Data仕様書__フォーマット.csv`）から読む。オフセットを手で書いていない。
  - 38 種類のレコードすべてで、項目が重ならずレコード長にちょうど収まることを確かめた（`layout.check_layout`）。
  - 生データの行は、どの種別も「仕様書のレコード長 − 2（CR/LF）」バイトだった。長さの合わない行は 0 行。
- 処理は 2 段。
  1. 取り込み: 生ファイル 1 つ × レコード種別ごとに、全版の行を `_stage/` に parquet で置く。ファイルの大きさと更新時刻が前回と同じなら読み直さない。
  2. 仕上げ: `_stage/` を全部合わせ、キーごとに最新版を残す。
- 時系列オッズ（0B41）は年ごとに `odds_ts_win/year=YYYY/part-NNN.parquet` に直接書く。年のフォルダのファイル数・大きさ・更新時刻が変わった年だけ作り直す。
- `--years` は読み直す生ファイル（`RACE/<年>.txt`、`SLOP/<年>.txt`、`0B41/<年>/`）を絞るだけ。仕上げは、それまでに取り込んだ全ファイルから作る。
- 全テーブルの作り直しは、12 コア・E: ドライブ読みで RACE 系が約 1 分、0B41 が約 12 分。

## 共通の約束

- **対象は JRA だけ**（競馬場コード 01〜10）。RACE に含まれる地方・海外のレース（データ区分 A・B）は落とす。
- **race_key** は 16 桁の文字列 `YYYYMMDDJJKKNNRR`（開催年・月日・競馬場・回・日目・レース番号）。JV-Link の速報系のキーと同じ形。
- 列名は英語の snake_case。仕様書の項目名との対応は各表の「仕様書の項目」に書いた。
- 数字として読めない値（すべて空白、`----`、`****` など）は null。仕様で「初期値 0」が「値なし」を意味する項目（着順、馬番、オッズ、人気など）も、0 を null にした。
- 時刻はすべて日本時間で、タイムゾーンを付けない（naive な datetime）。
- `data_kubun`（データ区分）と `created_date`（データ作成年月日）は、どの版を採ったかを残すために全テーブルに付けた。
- コード類（グレード・トラック・馬場状態・異常区分など）は仕様書のコードのまま文字列か整数で持つ。意味は「JV-Data仕様書 コード表」を引く。

### 版の選び方（重複除去）

RACE の年ファイルは**データを提供した年**で分かれている。
そのため、あるファイルに他の年のレースが入っていたり（例: `RACE/2024.txt` に 1989 年のレースの修正版が 425 件）、同じレースが複数の版で入っていたりする。
仕様書は「キーとデータ作成年月日を比べ、新しければ更新」と求めている（[JRA-VAN のページ](./jra-van.md)の「JVOpen の dataspec・fromtime・option」の節）。
そこで次の順に並べ、キーごとに最後の 1 行を残す。

1. `created_date`（データ作成年月日）が新しい。
2. 同じ日なら、データ区分の順位が高い。RA・SE は `1 < 2 < … < 7（成績）< 9（中止）< 0（削除）`。HR は `1（速報）< 2（成績）< 9 < 0`。O1 は `1 < … < 5（確定・月曜）< 9 < 0`。
3. それも同じなら、後に読んだ行（年ファイルの年順、その後に `RACE/update/` の日付順、ファイル内の行順）。

残った版がデータ区分 0（削除）なら、そのキーを消す。
データ区分 9（レース中止）は残し、races の `is_cancelled` を真にする。

キーは races が `race_key`、entries が `race_key` + `horse_id`、payouts と odds_final はレース単位（`race_key` ごとに 1 レコードを選び、そのレコードの行を全部残す）、マスタは各 id。
entries は、同じレースの中で最新版より低いデータ区分の行（出走馬名表にだけ載り、出馬表の前に回避した馬など）も落とす。
今の取り込み分（セットアップデータ）では、RA・SE の残った版はすべて 7（成績）か 9（中止）だった。

枠連オッズは取り込んでいない。

### odds_ts_win（0B41 時系列オッズ 単勝・複勝）

1 行 = 1 回の発表 × 1 頭。発表はすべて残す（間引かない）。
`year=YYYY` で分けた parquet（hive 形式）なので、`pl.scan_parquet("data/processed/jra-van/odds_ts_win/**/*.parquet", hive_partitioning=True)` で読む。

| 列 | 仕様書の項目 | 説明 |
|---|---|---|
| race_key | | ファイル名のキーとレコードのキーは全件一致 |
| announced_at | 発表月日時分 + 年 | datetime（分単位）。下の「発表時刻の年」 |
| data_kubun | データ区分 | 1 中間、2 前日売最終、3 最終、4 確定、5 確定（月曜）、9 レース中止 |
| umaban, win_odds, win_pop, win_status, place_odds_min, place_odds_max, place_pop, place_status | | odds_final と同じ |
| n_starters, win_sale_flag, place_sale_flag | | odds_final と同じ |
| win_vote_total, place_vote_total | 単勝・複勝票数合計 | 円。その発表の時点の累計。レース単位の値を各馬の行にくり返す |
| created_date | データ作成年月日 | |

- 発表時刻の年: 発表月日時分は月日時分（`mmddhhmm`）しかないので、年はレースの年で補う。発表の月がレースの月より 6 か月以上あとなら前年（1 月 5 日の金杯を 12 月に前日発売した場合など）、6 か月以上前なら翌年とする。今のデータでは読めない発表時刻は 0 件。
- 同じ分に 2 回の発表があることがある（同じ race_key・データ区分・発表月日時分で中身が違う）。単勝票数合計が多い方（後の発表）を残した。
- 「発走 N 分前に買う」ときは、`data_kubun == "1"`（中間）かつ `announced_at <= post_at - N 分` の最後の発表を使う。データ区分 3・4（最終・確定）は発走後に発表される（下の検証）。

### horses / jockeys / trainers（DIFN の UM・KS・CH）

1 行 = 1 頭 / 1 人。キーはそれぞれ `horse_id`・`jockey_code`・`trainer_code`。最新版だけ残す。
`DIFF/all.txt` は旧形式（UM が 1,575 バイトで仕様書の 1,607 と合わない）なので使わず、`DIFN/all.txt` だけを読む。

| テーブル | 列 |
|---|---|
| horses | horse_id, horse_name, horse_name_en, retired（競走馬抹消区分）, registered_date, retired_date, birth_date, sex_code, breed_code, coat_code, sire_id / sire_name（3代血統の 1 番目 = 父）, dam_id / dam_name（2 番目 = 母）, damsire_id / damsire_name（5 番目 = 母父）, belong_code, trainer_code, breeder_code, birthplace（産地名）, owner_code |
| jockeys | jockey_code, name, name_kana, name_short, name_en, retired, license_date, retired_date, birth_date, sex（1 男 2 女）, belong_code, apprentice_code, trainer_code（所属調教師、フリーは 00000）, invited_region |
| trainers | trainer_code, name, name_kana, name_short, name_en, retired, license_date, retired_date, birth_date, sex, belong_code, invited_region |

マスタは「今」の値（取得した日の所属・抹消状態）なので、過去のレースの特徴量に使うとリークになりうる。
レース時点の所属は entries の `belong_code`・`trainer_code` を使う。

### training_slope / training_wood（SLOP の HC・WOOD の WC）

1 行 = 1 回の調教。キー `center` + `train_date` + `train_time` + `horse_id`。

- 共通の列: center（トレセン区分 0 美浦 1 栗東）, train_date, train_time（`hhmm`）, horse_id。
- training_slope（坂路）: total_4f・total_3f・total_2f（800m〜0m などの合計）、lap_800_600・lap_600_400・lap_400_200・lap_200_0。秒。
- training_wood（ウッドチップ）: course（0 A 〜 4 E）, direction（0 右 1 左）, total_10f〜total_2f、lap_2000_1800〜lap_200_0。秒。
- 0（測定不良）と、WC の `9999` / `999`（上限超え）は null。

## 取り込んでいないもの

- O2（馬連）の時系列 0B42、O2〜O6 の確定オッズ、H1・H6（票数）、WF（WIN5）、JG（除外）。
- CK（出走別着度数）、BR・BN・RC・HN・SK などのマスタ。
- RA のラップタイム・コーナー通過順位（文字列）、SE の相手馬情報・マイニング予想。
- RACE の `update/` はまだ無い。できれば自動で読む（速報版のデータ区分 1〜6 は、上の版の選び方で成績に置き換わる）。

### 読み方と未解決の点

- 最新版の RA・SE はすべてデータ区分 7（成績）か 9（中止）。中止は 422 レース（大雪・台風などの開催中止）。
- 1986 年以降、1 着の馬がいないレースは 0 件。1 着が 2 頭のレース 177 件はすべて同着区分が 1。
- 単勝の払戻馬番が SE の 1 着馬と違う 2 件（2014 年・2020 年）は、どちらも払戻の馬が SE で異常区分 5（失格）・入線順位 1。払戻の確定後に失格が決まり、払戻はそのままだったと考えられる（推測）。払戻は payouts を正とする。
- O1 の単勝オッズが値を持たない 7,795 行（両方に馬番がある 1,595,524 行と、両方に値がある 1,587,729 行の差）は、SE でも単勝オッズが null（取消・除外）。SE だけ・O1 だけに値がある行は 0。
- 0B41 の複勝は、出走 4 頭以下で複勝を発売しないレースでは馬番ごと空白になる（2006 年の 188 行で、単勝の馬番と複勝の馬番が食い違ったのはこれ）。そのとき複勝の列は null。
- 発走時刻（races の `post_at`）は予定の時刻で、発走の遅れは入っていない。中間オッズ（データ区分 1）が予定の発走時刻より後に出たのは 491 レースの 504 発表で、遅延したレースと考えられる（最大 43 分後）。「発走 N 分前」を予定時刻で決めると、遅延したレースでは実際より早い時点を取るので、安全側にずれる。
